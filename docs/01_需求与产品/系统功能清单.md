# 鲸选美学 CRM 系统功能清单

本文按当前源码、实际页面和接口契约整理，用于运营培训、功能验收和后续规划。

## 先说明：“公开知识问答未开放”是什么

**公开知识问答**是指普通用户或客户在一个问答页面里直接输入问题，由系统根据允许使用的知识资料给出有出处的回答。例如，用户询问“某机构可以做哪些项目”，系统只根据允许公开的项目资料回答，并给出来源。

它**不是**素材库、知识库配置或资料同步功能。当前状态需要分开理解：

- **已经具备**：素材创建、修订、审核、发布、同步、失败重试、停用，以及知识库连接配置和内部受控接口。
- **尚未开放**：面向普通用户或客户的公开问答页面和匿名提问能力，即“用户自己提问”的入口。
- **仍需联调**：真实 Dify 及模型服务需要供应商授权、部署合规确认和真实环境验收；模拟同步不代表真实服务已联通。

如果未来建设这项能力，应只使用**已审核且允许公开的资料**，并提供答案依据。不得因此开放客户档案、订单、合同、私人聊天或其他敏感资料，也不得让 AI 自动确认支付、核销、退款或银行资料变更。

因此，“公开知识问答未开放”不等于“知识资料管理没做”，而是**资料管理能力已有，面向用户的自由提问功能尚未开放**。

## 一、角色使用范围

| 角色 | 主要使用范围 |
|---|---|
| 系统管理员 | 系统配置、用户角色及授权范围内的全部业务 |
| 经营负责人 | 经营报表、业务数据和授权范围内的只读查看 |
| 管家主管 | 团队客户、任务、转交审核、履约及团队业绩 |
| 管家 | 本人客户、跟进、订单、预约、退款申请、素材和本人业绩 |
| 商务运营 | 机构合作、产品活动、渠道、素材及市场审批 |
| 财务 | 退款审批执行、机构财务审批、冲正审核、结算核准与付款 |
| 机构前台 | 预约接诊、到院、服务完成等接待操作，不直接正式核销 |
| 机构操作员 | 本机构预约处理及最终正式核销 |
| 机构财务 | 本机构结算、核销和对账只读查看 |

实际可用功能还取决于账号角色、数据范围和机构授权，不能只根据菜单判断。没有权限的模块不展示或明确不可查看，不把“无权限”当成“数量为零”。

## 二、功能清单

### 1. 工作台与通用操作

- 按管理员、管家和机构用户展示不同工作台、菜单、待办和快捷入口。
- 管家首页展示本月净支付（支付减退款）、支付与退款金额，以及权限范围内有效可用的剩余服务次数和涉及客户数。
- 列表分页、组合筛选、状态标签、详情抽屉、列设置。
- 表单校验、重复提交防护、操作失败提示。
- 算术图片验证码5分钟有效且一次性使用，点击可刷新；登录失败限流，登录保护存储异常时不跳过校验。
- 登录、退出、当前用户信息、无权访问和页面不存在提示；密码重置后立即吊销该用户全部旧会话。

### 2. 客户与归属管理

- 新建、编辑、查询客户档案；客户编号由系统生成。
- 姓名、昵称、手机号、城市、来源、渠道、等级、生日、关注项目和备注。
- 客户标签、积分余额及积分调整流水。
- 客户身份与外部身份关联，敏感信息脱敏。
- 手机号及外部身份查重、合并候选、人工审核确认。
- 合并后的身份、标签、跟进、任务和积分流水迁移。
- 已确认合并支持更正申请、审批、执行和人工完成确认。
- 客户转交申请、审核、驳回、归属历史及操作记录。
- 原客户信息表字段映射查看；未导入字段明确标记，不把映射查看当成完整历史迁移。

### 3. 跟进与任务

- 登记、修改、软删除客户跟进，更新最近跟进时间。
- 设置下次跟进时间后自动创建回访任务，同一跟进不重复生成；改期仅同步待处理任务，处理中、已完成和已取消的任务不会被重置。负责人账号停用时由实际操作人承接，不批量补建历史任务。
- 新建任务、设置类型、优先级、截止时间和说明。
- 任务接手、转派、退回任务池和完成。
- 查询任务处理记录、负责人变化及状态。
- 支持本人、团队、授权范围和待处理任务池。
- 按真实截止时间统计今日到期及已逾期任务。

### 4. 产品、套餐与 SKU

- 标准服务项目管理。
- 套餐主定义、版本、子项目和权益规则配置。
- 固定项目、选 N 项等模式；未明确的选择规则不能自动发放权益。
- 套餐版本激活、归档和历史快照查看。
- SKU 新建、编辑、上架、停用及适用机构配置。
- 已售规则保留历史快照，不用新规则覆盖旧订单。
- SKU 销量、低频和质量提示；只提示，不自动下架。

### 5. 订单、支付与权益

- 新建订单草稿，选择客户、SKU、数量、金额和有效期。
- 保存订单类型、活动、渠道、收款方和销售归属快照。
- 提交待支付、取消订单、查看订单详情。
- 有权限的人员进行人工支付确认并填写凭证引用。
- 重复支付确认不会重复生成支付记录或发放权益。
- 支付确认后按销售时快照发放项目权益。
- 查询权益批次、可用次数及发放、核销、退款回收等流水。
- 已支付金额和项目等历史事实不直接覆盖。

### 6. 预约与机构核销

- 管家创建预约，选择客户、机构、时间和权益项目。
- 预约只记录计划次数，不提前扣减权益。
- 机构确认接诊、拒绝接诊、到院、服务完成和爽约。
- 机构授权操作员执行正式核销，前台和管家不能直接正式核销。
- 核销后按项目扣减次数并保留流水。
- 查询预约、核销详情和逐项目记录。
- 已正式核销需要更正时，申请冲正并由授权人员审核，不直接修改历史。
- 支持跨机构访问拒绝、重复核销防护和状态冲突检查。

### 7. 退款管理

- 创建退款申请，填写金额、原因及需要回收的权益。
- 退款审批、驳回、登记执行、退款成功或失败记录。
- 人工核对银行转账、线下退款凭证后确认结果。
- 只有实际退款成功才累计退款金额并回收对应权益。
- 申请人与审批人分离，不直接覆盖退款成功记录。
- 查询退款申请、审批、执行、成功确认及历史凭证。

### 8. 机构合作管理

- 机构主档创建、编辑、查询和激活。
- 业务类型、机构性质、等级、城市、联系人、结算方式及费率等资料。
- 银行、税号等敏感资料加密保存、按权限脱敏。
- 普通资料编辑与敏感资料变更分开。
- 机构激活和敏感变更支持市场、财务审批；双审不得由同一人完成。
- 资料版本冲突时重新复核，不覆盖生效档案。
- 合同版本登记、续签管理和激活审批。
- 资质文件登记、审核、到期信息及凭证管理。
- 机构产品库支持按机构、项目、医生、仪器和案例检索；一页纸展示真实资料数量与明细。
- 医生、仪器、案例资料支持新增、编辑、下架和恢复展示；下架保留历史与审计，不做物理删除。
- 可选附件限同机构私有文件，须通过安全扫描后引用；一页纸不展示银行、税号、佣金或合同金额。
- 机构用户拥有独立工作台、预约接待、核销和结算入口。

### 9. 活动与合作渠道

- 活动创建、修改、批次新增和修改。
- 活动时间、状态及批次管理。
- 订单保留活动与批次归属快照。
- 合作达人、推广渠道、负责商务及合作状态管理。
- 活动成交、支付、退款和履约等经营分析。
- 不擅自计算尚未确认口径的转化率。

### 10. 数据经营与运营大屏

- 支付、成功退款、净支付、支付订单、到院客户和正式核销。
- 新增客户、待办回访、待确认预约、待核销和待审批退款。
- 日趋势、履约阶段、机构核销排行、活动与批次排行。
- 按日期、订单来源、收款方和授权机构筛选。
- 显示业务数据水位、最近刷新时间及加载失败状态。
- 数字按类别使用不同配色，并在真实数据变化时滚动更新。
- 自动刷新可暂停、恢复，也支持手动刷新。
- 支持全屏、待办处理入口和空状态引导。
- 原有履约、机构、活动图表通过“更多经营分析”保留。
- 管家及商务业绩、每日明细、目标完成情况和事实明细查询。

### 11. 导出与风控

- 客户、订单、核销和跟进数据的授权导出。
- 导出任务列表、状态、异步生成和私有下载。
- 导出申请及下载审计记录。
- 风险台账分页、详情、认领、处理和关闭。
- 风险处理保留追加历史，不自动修改资金或权益账本。
- 普通管家和机构账号不能因此获得内部风控数据。

### 12. 素材管理

- 素材创建、修改、版本新增、送审、审核和下架。
- 按类型、城市、机构、项目和标签管理素材。
- 私有文件上传、校验、病毒扫描和临时授权下载。
- 只有符合安全和权限要求的文件才能预览或下载。

### 13. 知识资料

- 将已审核素材版本发布到知识资料同步队列。
- 查看同步状态、失败原因、重试失败任务和停用知识资料。
- 配置知识库连接并执行连接测试。
- 公开问答仍未开放；Mock 同步不等于真实 Dify 联通。

### 14. AI 与企业微信

- 大模型供应商、地址、模型、密钥和模拟模式配置。
- 对授权会话创建证据提取或分析任务。
- 查看 AI 任务、证据、建议及失败状态。
- 人工确认或驳回 AI 建议。
- 主管会话质量建议统计。
- AI 不自动确认订单、支付、核销、退款或银行资料变更。
- 企微外部联系人、同意状态、成员覆盖和客户身份人工匹配。
- 授权消息元数据查询、按需读取正文、归档同步及覆盖缺口监控。
- 不使用个人微信，不在未确认同意和权限时采集。
- 企微真实归档授权及官方 SDK 联调仍未完成，未读回执也尚未接入。

### 15. 有赞与外部集成

- 有赞原始订单查询、详情和内部订单关联。
- 外部 SKU 与 CRM SKU 映射。
- 外部客户与 CRM 客户人工映射。
- 订单同步、补偿轮询、同步异常查询及人工重试。
- 店铺授权配置、连接测试、同步任务及同步策略。
- 官方消息回调验签后查询订单详情。
- 外部集成全局开关保存后即时生效。
- 当前默认使用 Mock/禁用真实接入；模拟回调不代表真实资金到账。

### 16. 系统管理与安全

- 用户创建、编辑、分配角色、停用及会话吊销。
- 角色创建和权限分配，权限变更下一请求生效。
- 团队选项、权限目录和角色权限查看。
- 字典选项新增、改名、排序和停用；历史数据继续保留。
- 业务操作审计、操作人、对象、时间及变更前后快照。
- 私有文件分类权限、哈希校验、病毒扫描和签名下载。
- 数据查询按租户、本人、团队或机构范围限制。
- 错误请求具有稳定提示和请求编号。

## 三、关键业务约束

- 只有经过授权的人工或可信支付确认后，才发放权益。
- 预约由管家创建，合作机构授权操作员最终确认核销。
- 只有正式核销事件才扣减可用次数。
- 只有实际退款成功才累计退款金额并回收对应权益。
- 已支付订单金额、正式核销、退款成功及审核生效等历史事实，不直接覆盖。
- 机构资料变更必须经过规定审批；需要双审时，审批人不能是同一人。
- AI 只能提供建议或辅助信息，不能自动确认支付、核销、退款或银行资料变更。
- 文件必须经过安全校验和病毒扫描，受权限控制后才能使用或下载。
- 真实供应商未授权前只使用 Mock 或禁用状态，不把模拟成功当成真实联通。

## 四、尚未实现或仍受限制的功能

这里的“未实现或受限”不代表整个模块都不能使用。下表分别说明缺少的能力、目前可用的部分和实际影响；需要真实外部服务的能力，不以模拟结果冒充正式结果。

| 事项 | 通俗解释 | 当前状态与影响 |
|---|---|---|
| **可拖拽工作流配置** | 指运营人员在页面上拖动“发起、审批、通知、完成”等节点，设置办理人、条件和分支，并保存为可启用的业务流程。 | 目前有的是普通待办任务和按既定规则运行的审批流程，**不是完全没有任务或审批**。尚未提供通用拖拽编辑器、条件分支配置、流程试运行、版本发布/停用和按流程查看执行记录，运营人员不能自行拖拽改变审批步骤。 |
| **机构账号映射与员工数据范围管理入口** | “机构账号映射”决定某个机构登录账号属于哪家机构，例如机构 A 的账号只能处理机构 A 的预约、核销和结算；“员工数据范围”决定员工能查看本人、团队或授权范围内的哪些客户。 | 后台已有相关数据结构和访问范围校验，跨机构、跨管家访问仍会被拒绝；但缺少让管理员在页面完成映射和数据范围维护的完整管理入口及接口。当前部分验收使用隔离测试数据完成，**测试数据不能当作运营配置功能**，正式环境也不应长期依赖直接修改数据库。 |
| **真实有赞、企微、Dify 和模型服务** | 指系统真正连接已授权的店铺、企业微信和模型服务，而不是由系统内的模拟功能返回结果。 | 已有配置、连接测试和 Mock（模拟）能力，可用于验证内部流程；真实使用仍需供应商授权、密钥安全配置、官方接口及回调联调、测试环境验收。企微还须先确认客户同意、可采成员和权限。**模拟成功不代表真实资金到账、真实聊天已采集或真实模型已联通。** |
| **公开知识问答** | 指普通用户或客户自己输入问题，由系统根据允许公开的资料生成带来源的回答，例如查询机构公开项目介绍。 | 目前开放的是内部素材审核、知识资料发布、同步、重试、停用和连接配置；没有面向普通用户或客户的自由提问页面，也未开放匿名提问。内部受控接口不等于公开问答。未来开放时只能使用已审核且允许公开的资料，不能泄露客户档案、订单、合同或聊天内容。 |
| **企微未读回执** | 指企业微信明确返回某条消息是否已读，以及对应的已读状态。 | 当前尚未接入可靠的已读/未读回执，因此不能展示真实未读数，也不能把“消息尚未归档”或“客户一段时间未说话”认定为客户未读、员工未回复。现有超时沉默提示和 AI 风险建议只是辅助线索，不应直接作为处罚或考核事实。 |
| **历史数据迁移** | 指把旧客户表、历史订单等数据经过字段对应、格式校验、去重、导入和数量金额核对后，正式迁入系统。 | 当前有原客户信息表的字段映射查看，以及部分恢复、对账能力，**但“能看到字段映射”不等于“可以批量导入”**。仍缺来源字段确认、完整校验、导入执行、结果对账和业务签字确认，不能把旧表格直接当作正式业务账。 |
| **正式生产上线** | 指系统部署到真实公网环境后，能够持续、安全地为真实用户服务，并在故障时恢复数据，而不仅是安装成功或核心流程演示通过。 | 安装包和核心业务流程验证不等于正式上线验收。后端框架 Spring 仍有两项已确认的高危安全漏洞需要升级复测，还需配置真实公网 HTTPS、生产高可用和监控，并完成数据库恢复演练。**已经生成备份、通过压缩包完整性检查，不代表数据已经恢复成功。** |

### 真实外部服务还需要什么
