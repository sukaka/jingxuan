# 15 原始业务表 → V2.0 页面 → 正式数据实体映射

> 来源为已提供的原管家填表规范、客户信息表 23 字段截图、九类其他业务表截图，以及 V2.0 原型。截图中字段被截断、自动计算公式未提供的部分标注“待确认”，不强行臆造。

## 1. 客户信息表 23 字段原名逐项保留
| 原字段 | 新系统展示 | 业务实体/建议字段 | 实施说明 |
|---|---|---|---|
| 用户姓名 | 客户档案 | `crm_customer.display_name` | 可为空，昵称至少存在 |
| 客户昵称 | 客户档案 | `crm_customer.nickname` | 与真实姓名区分 |
| 客户电话 | 客户档案 | `mobile_cipher/mobile_hash` | 可空，密文+盲索引，不能作PK |
| 客户来源 | 客户档案 | `source_code` | 与渠道独立，历史来源需映射 |
| 客户渠道 | 客户档案 | `channel_code` | 不与来源合并 |
| 新客/老客 | 客户档案 | 推荐新增 `new_old_code` | 是否自动计算需确认 |
| 所在城市 | 客户档案 | `city_code` | 系统字典动态维护 |
| 关注项目 | 客户档案 | `attention_projects` | 原表公式/关联规则需核对 |
| 所属管家（真实姓名） | 客户归属 | `owner_staff_id` | 员工ID，历史转交日志 |
| 所属账号 | 客户归属 | 建议新增 `owner_account_id` | 账号语义待确认 |
| 填写者（填写账号名称） | 操作审计 | `created_by/legacy_writer` | 旧字段来源待核对 |
| 电话-是否重复 | 客户查重 | `crm_merge_case` / computed | 不保存为人工填写判断 |
| 下单数 | 客户统计 | 聚合CRM有效订单 | 旧公式与新口径分别保存 |
| 订单总金额 | 客户统计 | 聚合订单原价/实付分别显示 | 不得与累计实付混用 |
| 客户状态 | 客户管理 | `customer_status` | 动态字典 |
| 提交时间 | 原数据审计 | `legacy_submitted_at` | 不能默认等于创建时间 |
| 客户首次入库时间 | 客户来源时间线 | `legacy_first_import_at` | 与客户添加时间不同 |
| 客户添加时间 | 客户来源时间线 | `first_added_at` | 是否企微添加需核实 |
| 首次下单时间 | 客户统计 | `first_order_at` | 源订单证据决定 |
| 最后一次跟进时间 | 客户运营 | `last_followup_at` | 依真实跟进计算 |
| 卡点情况 | 客户档案/AI | `blocker_note` | 原公式需核对；AI建议分开 |
| 备注 | 客户档案 | `remark` | 非结构化备注 |
| 备注名 | 客户档案 | `remark_name` | 与客户昵称分开 |

这些原字段的 `legacy_*` 辅助存储可放在 `crm_customer_legacy` 扩展表或 `legacy_source_map`（待 P0-1 时补迁移），**不是说基线 schema 已完整覆盖所有 23 个原字段的最终结构**。

## 2. 其余截图的业务表对应
| 原始表/视图 | 新页面 | 主要实体 | 必须防错 |
|---|---|---|---|
| 机构信息维护表 | 机构中心 | institution、contract、qualification、profile_change_request | 财务/佣金变更需审批 |
| 产品组合项目明细表 | 产品/套餐 | package、package_version、package_project、sku | 选N项与N次分开 |
| 3.1 产品子项目明细表 | 子项目库 | project | 编码唯一，不因商品改价破坏历史 |
| 合作渠道信息表 | 合作渠道 | partner_channel / campaign | 商务归属快照 |
| 客户日跟进表 | 每日跟进台账 | followup、task | 每次跟进新流水，不覆盖原对话 |
| 管家售卖登记表 | 订单中心 | order、order_item、payment、refund | 成交日期不是支付证据 |
| 订单核销明细表 | 核销记录 | appointment、redemption、entitlement_ledger | 院方最终确认，反复点击不双扣 |
| 管家业绩表 | 我的业绩/团队业绩 | reporting read model | 口径审批/历史归属 |
| 商务业绩表 | 商务业绩 | reporting read model | 不与管家业绩混算 |
| 客户管理动态看板 | 客户运营/工作台 | task、followup/aggregations | “未回复”依消息覆盖率 |
| 日沟通汇总/大促统计 | 运营/活动中心 | campaign、batch、report | 时间窗口与分母明示 |

## 4. 不能直接依原型判定完成的事项
V2.0 为纯前端；市场/财务/主管专属后台在原型中不是全功能的独立身份；你们原表截图中部分关联公式/字段名称被截断；有赞/企微/HIS 接口真实权限尚未联调；机构结算和退款规则未最终签字。开发过程中均应标为未验证/待确认，决不能声称已经生产实现。
