# 16 全系统流程泳道图

本文将鲸选美学 CRM 的主要业务、外部协作和系统支撑流程统一表示为泳道图。依据为当前 PRD、状态机、角色权限、实际接口及功能清单；流程状态与限制以仓库最新实现为准。

## 1. 阅读说明

- 使用 Mermaid `sequenceDiagram`：**每个参与者列就是一条泳道**，箭头表示职责交接、系统调用或事实写入，虚线表示响应/结果。
- `alt` 表示互斥分支，`opt` 表示可选环节，`loop` 表示重复执行，`Note` 表示不可绕过的约束或现状边界。
- 覆盖有明确业务动作、状态变化或跨角色协作的流程。单纯列表查询、详情查看、分页、列设置不逐页重复成图，但仍受登录与数据权限流程约束。
- 除匿名外部回调外，写操作默认经过后端 RBAC、租户与数据范围校验；需要防重的命令携带幂等键，需要防并发覆盖的表单携带 `version`，并按领域要求校验 CSRF、记录审计。
- 图中“CRM”包含后端应用服务与 MySQL 事务，不表示把所有职责放进 Controller；MySQL 是业务事实源，Redis 和 Kafka 不代替账本。
- “模拟/Mock”只验证内部链路，不代表真实供应商授权、真实资金到账或生产验收。公开知识问答、个人微信采集、AI 自动确认资金/核销均不是现有能力。

### 流程地图

| 分类 | 覆盖流程 |
|---|---|
| 经营主链路 | 获客 → 建档 → 跟进 → 下单支付 → 权益 → 预约核销 → 退款/结算 → 回访与经营分析 |
| 客户与任务 | 登录访问、建档与积分、跟进任务、查重合并、合并更正、归属转交 |
| 产品与交易 | 套餐/SKU、手工订单、有赞订单、预约核销、核销冲正、退款 |
| 机构与合作 | 机构准入与敏感变更、合同资质、展示资料、结算付款、活动渠道归因 |
| 外部与智能 | 企微客户资料、企微会话归档、AI 证据提取与人工确认 |
| 内容与运营 | 文件、素材、知识资料、报表大屏、导出、风控与对账 |
| 系统与运维 | 用户角色权限、字典、Outbox/Kafka/Inbox、数据迁移、备份恢复与发布 |

## 2. 端到端经营履约总览

```mermaid
sequenceDiagram
  actor CH as 达人/内容/渠道
  actor M as 管家
  participant CRM as CRM 业务服务
  actor F as 财务/授权支付确认人
  actor I as 合作机构
  actor C as 客户

  CH->>CRM: 带来线索、来源与渠道信息
  M->>CRM: 建档或认领客户，明确归属管家
  M->>CRM: 合规沟通、登记跟进与回访任务
  M->>CRM: 选择有效 SKU，创建并提交订单
  alt 人工收款
    F->>CRM: 核验真实凭证并确认支付
  else 有赞来源
    CRM->>CRM: 验签、拉取详情、映射客户/SKU并核实支付
  end
  CRM->>CRM: 同一事务记支付、订单 PAID、GRANT 权益及 Outbox
  M->>CRM: 选择机构、权益项目和计划次数创建预约
  CRM-->>I: 展示本机构待接诊预约
  I->>CRM: 确认接诊 → 到院 → 服务完成
  C->>I: 到院并接受服务
  I->>CRM: 授权操作员最终确认正式核销
  CRM->>CRM: 同一事务写 POSTED、REDEEM 负流水并更新余额
  opt 发生退款
    M->>CRM: 提交退款申请及权益处理方案
    F->>CRM: 异人审批、执行并核验成功结果
    CRM->>CRM: 仅成功后退现金账并追加 REFUND_REVOKE
  end
  F->>CRM: 基于真实核销与规则快照核准结算、登记付款
  M->>CRM: 服务回访、复购跟进
  CRM-->>M: 在授权范围内展示业绩与经营事实
```

**主线不变量：**支付确认前无可用权益；预约不提前扣次数；只有机构授权操作员正式核销才扣减；只有真实退款成功才累计退款并回收权益。

## 3. 客户、任务与访问流程

### 3.1 登录、会话恢复、访问控制与退出

```mermaid
sequenceDiagram
  actor U as 用户
  participant W as CRM Web
  participant A as 认证与权限服务
  participant B as 业务接口/MySQL

  U->>W: 输入用户名和密码
  W->>A: POST /auth/login
  A->>A: 校验 ACTIVE 用户、BCrypt 密码并创建服务端会话
  alt 登录失败
    A-->>W: 统一 401，不区分用户不存在或密码错误
    W-->>U: 显示失败原因，不泄露账号存在性
  else 登录成功
    A-->>W: HttpOnly JWT Cookie + CSRF Cookie
    W->>A: GET /auth/me 恢复用户、角色、权限与机构角色
    A-->>W: 返回实时权限信息
    U->>W: 访问页面或提交操作
    W->>B: 请求业务接口；写请求携 CSRF/幂等/version
    B->>B: 再校验 RBAC、租户、本人/团队/机构范围和字段权限
    alt 未登录、越权或状态冲突
      B-->>W: 401/403/404/409 等稳定错误及 requestId
    else 校验通过
      B-->>W: 返回业务结果
    end
  end
  U->>W: 退出
  W->>A: POST /auth/logout
  A->>A: 吊销服务端会话并写审计
  A-->>W: 清除 Cookie
```

### 3.2 客户建档、身份关联与积分调整

```mermaid
sequenceDiagram
  actor M as 管家/主管/管理员
  participant CRM as 客户服务/MySQL
  participant EXT as 官方外部身份来源

  M->>CRM: 新建客户，填写称呼、来源、渠道及合格归属管家
  CRM->>CRM: 校验数据范围，生成独立 customerId/customerNo
  CRM->>CRM: 手机号可空；密文保存并建立盲索引，响应默认脱敏
  opt 存在企微/有赞等外部身份
    EXT-->>CRM: 提供外部身份标识，不直接决定客户主键
    M->>CRM: 人工确认身份关联并填写理由
    CRM->>CRM: 保存 identity/link，保留来源和审计
  end
  CRM-->>M: 返回客户档案；重复线索只形成合并候选
  opt 调整积分
    M->>CRM: 提交非零调整数量与原因
    CRM->>CRM: 校验 customer:points_adjust、客户范围和幂等键
    alt 无权限或调整后余额将为负
      CRM-->>M: 403/404/409，不直接改余额
    else 调整合法
      CRM->>CRM: 追加 MANUAL_ADJUST 正负流水，同事务重算余额缓存
    end
  end
```

> 客户唯一 ID 不等于手机号、昵称或外部平台身份。Q12 的积分规则未确认前，不做自动消费积分推断。

### 3.3 跟进登记与任务接手、转派、退回、完成

```mermaid
sequenceDiagram
  actor M as 管家/任务负责人
  participant CRM as 跟进与任务服务
  actor L as 主管/管理员

  M->>CRM: 登记客户跟进、沟通摘要和下次跟进时间
  CRM->>CRM: 校验客户范围，追加跟进并更新最近跟进时间
  opt 误录修正或软删除
    M->>CRM: 修改允许字段或说明原因后软删除
    CRM->>CRM: 保留审计，不改写企微原始归档
  end
  M->>CRM: 创建任务，设置团队、类型、优先级和截止时间
  CRM-->>M: OPEN；可进入本人任务或同组未分配任务池
  alt 接手任务池
    M->>CRM: claim(version + 幂等键)
    CRM->>CRM: OPEN → PROCESSING，记录负责人和 claimedAt
  else 主管转派
    L->>CRM: reassign(目标成员 + reason + version)
    CRM->>CRM: 校验本组 ACTIVE 员工，更新负责人并追加动作日志
  else 退回任务池
    M->>CRM: return(reason + version)
    CRM->>CRM: PROCESSING → OPEN，清空当前负责人，保留首次负责人
  end
  M->>CRM: complete(version + 幂等键)
  CRM->>CRM: 仅 PROCESSING → DONE，写 completedAt
  CRM-->>M: 返回任务状态与只追加动作历史
```

### 3.4 客户查重、审核与合并

```mermaid
sequenceDiagram
  actor M as 管家/主管
  participant CRM as 客户合并服务/MySQL
  actor R as 有权限审核人

  M->>CRM: 发起查重扫描
  CRM->>CRM: 按手机号盲索引、外部身份等生成候选
  CRM-->>M: SUGGESTED；昵称相似本身不构成合并依据
  M->>CRM: 开始审核，选择主客户和从客户
  CRM->>CRM: 校验双方数据范围并锁定主/从档案
  CRM-->>R: REVIEWING，展示待迁移资源和冲突
  alt 驳回
    R->>CRM: reject(理由)
    CRM->>CRM: REJECTED，不迁移任何数据
  else 确认合并
    R->>CRM: confirm(版本 + 幂等键)
    CRM->>CRM: 保存将迁移资源的 ID 快照
    alt 订单/权益已有预约、核销或退款关联
      CRM-->>R: CONFLICT，保留历史事实并停止自动迁移
    else 校验通过
      CRM->>CRM: 事务迁移身份、标签、跟进、任务、积分及允许迁移的关联
      CRM->>CRM: 从客户软归档，重算积分缓存，合并单 CONFIRMED
      CRM->>CRM: 追加审计，保留原 ID 映射和全部账本历史
    end
  end
```

### 3.5 错误合并更正

```mermaid
sequenceDiagram
  actor A as 更正申请人
  participant CRM as 合并更正服务/MySQL
  actor R as 合并更正审批人

  A->>CRM: 对已 CONFIRMED 合并提交更正申请
  CRM->>CRM: 校验双方数据范围、原合并状态和幂等键
  CRM-->>R: 更正单 REQUESTED
  alt 审批驳回
    R->>CRM: reject(理由)
    CRM->>CRM: REJECTED；客户和原合并结果不变
  else 审批执行
    R->>CRM: approve(version + 幂等键)
    alt 有合并前资源快照
      CRM->>CRM: 检查快照中待迁回订单/权益是否已有新业务关联
      alt 存在受保护关联
        CRM-->>R: CONFLICT/ERROR，事务回滚并保留脱敏审计
      else 可自动撤销
        CRM->>CRM: 仅按快照 ID 迁回，恢复从客户并重算双方积分
        CRM->>CRM: 原合并单改 REVERSED，历史不删除
      end
    else 历史合并无快照
      CRM->>CRM: 只恢复从客户，进入 MANUAL_REVIEW
      R->>CRM: 人工逐项处理并填写完成说明
      CRM->>CRM: complete 后原合并单才改 REVERSED
    end
  end
```

> 主客户原有及合并后新增的数据不会被全量迁回；去重删除的身份/标签不能自动恢复。支付金额、权益发放和核销历史不被覆盖。

### 3.6 客户归属转交

```mermaid
sequenceDiagram
  actor M as 原管家/主管
  participant CRM as 归属转交服务/MySQL
  actor A as 主管/管理员
  actor N as 新管家

  M->>CRM: 选择客户与合格新管家，提交转交申请
  CRM->>CRM: 校验当前归属、baseVersion、数据范围和审批路径
  CRM-->>A: PENDING；客户当前归属暂不变
  alt 驳回
    A->>CRM: reject(理由)
    CRM->>CRM: REJECTED，保留原归属与申请历史
  else 批准
    A->>CRM: approve(version + 幂等键)
    CRM->>CRM: 再次检查 baseVersion 和跨团队权限
    alt 客户已被其他流程变更
      CRM-->>A: 409，要求刷新后重新复核
    else 生效
      CRM->>CRM: PENDING → APPROVED → EFFECTIVE
      CRM->>CRM: 更新当前归属并追加不可覆盖的 ownerHistory
      CRM-->>N: 新管家在本人范围内可见客户
    end
  end
```

> 历史订单继续保留成交时的销售与归属快照，不因后续转交改写业绩事实。

## 4. 产品、交易与履约流程

### 4.1 产品、套餐、SKU 上架与停售

```mermaid
sequenceDiagram
  actor O as 产品运营/商务
  participant CRM as 产品目录服务/MySQL
  actor M as 管家/机构用户

  O->>CRM: 维护标准子项目与套餐主定义
  O->>CRM: 新建套餐 DRAFT 版本并配置项目、次数和规则
  CRM->>CRM: 校验编码唯一、整数分金额、项目与机构有效性
  alt “选 N 项”明细规则未明确（Q01）
    CRM-->>O: 可保存模板，但 entitlementIssuable=false
  else 固定项目或规则完整
    CRM-->>O: 版本具备后续发放配置条件
  end
  O->>CRM: 激活套餐版本
  CRM->>CRM: DRAFT → ACTIVE，冻结已激活版本规则
  O->>CRM: 创建 SKU，配置售价、有效期与适用机构
  O->>CRM: 上架 SKU
  alt 权益规则不完整
    CRM-->>O: 422 PENDING_BUSINESS_RULE，保持停用
  else 校验通过
    CRM->>CRM: SKU ACTIVE，可被有效订单选择
  end
  M->>CRM: 查询本人/本机构可用的 SKU 与版本快照
  CRM-->>M: 仅返回授权范围，不返回机构敏感财务字段
  O->>CRM: 停售 SKU 或归档未来不再使用的版本
  CRM->>CRM: 新订单不可再选；历史成交快照与订单不变
```

> Q02 分摊权重未配置时保存待分摊标识并阻断相关金额结算，不阻断合规的目录维护。低频或质量提示只辅助运营，不自动下架。

### 4.2 手工订单、支付确认与权益发放

```mermaid
sequenceDiagram
  actor M as 管家
  participant CRM as 订单支付权益服务/MySQL
  actor F as 财务/授权支付确认人
  participant K as Outbox/Kafka

  M->>CRM: 创建 DRAFT，选择客户、SKU、数量、活动/渠道和收款方
  CRM->>CRM: 冻结 SKU/套餐版本/项目/次数/机构/有效期及归属快照
  alt Q01 规则未明确或 SKU/批次不可用
    CRM-->>M: 422/409，不建立可发放订单
  else 草稿有效
    M->>CRM: 提交订单
    CRM->>CRM: DRAFT → PENDING_PAYMENT，追加状态历史
    opt 未支付取消
      M->>CRM: cancel(version + 幂等键)
      CRM->>CRM: CANCELED，不产生支付或权益
    end
    F->>CRM: 核对 BANK_TRANSFER/OFFLINE 真实凭证并确认支付
    CRM->>CRM: 锁订单，校验权限、金额、交易号、凭证和请求哈希
    alt 同键同请求重放
      CRM-->>F: 返回首次结果，不重复入账
    else 金额/交易号/请求冲突
      CRM-->>F: 409，事务不写资产
    else 首次有效确认
      CRM->>CRM: 单事务写 CONFIRMED 支付、订单 PAID、历史与审计
      CRM->>CRM: 按成交快照逐项目写权益批次和 GRANT 正流水
      CRM->>K: 同事务写 Outbox，异步发布 order.paid.v1
      CRM-->>F: 返回支付事实与权威权益余额
    end
  end
```

> 已支付订单的金额、项目和成交快照不能通过普通编辑覆盖。管家不能自行确认支付，AI 也不能触发此流程。

### 4.3 有赞订单同步、映射与异常补偿

```mermaid
sequenceDiagram
  actor A as 集成管理员
  participant Y as 有赞官方平台/Mock Adapter
  participant CRM as 有赞适配与交易域
  actor O as 运营排障人员

  A->>CRM: 配置店铺、同步策略、运行开关及 SKU/客户映射
  CRM->>CRM: 密钥加密保存，校验 Q11/真实开关与数据范围
  alt 官方消息回调
    Y->>CRM: 发送官方签名消息
    CRM->>CRM: 验签、限制报文、保存 Raw 并去重
    CRM-->>Y: 202 仅表示接收，不表示支付成功
    CRM->>Y: 延迟查询订单详情，失败按有界策略重试
  else 手动/定时同步或补偿
    A->>CRM: 发起 sync/reconcile，或调度器认领任务
    CRM->>Y: 按时间窗、游标和分页拉取订单及详情
    Y-->>CRM: 返回订单；Token/限流/租约按店铺处理
  end
  CRM->>CRM: 外部 DTO 转内部模型，脱敏/加密保存原始引用
  alt SKU 未映射或客户未人工确认
    CRM->>CRM: MAPPING_FAILED/CUSTOMER_UNRESOLVED，建立 OPEN 异常
    O->>CRM: 修正 ACTIVE SKU 映射或客户链接
    O->>CRM: retry(原异常 + 幂等键)
    CRM->>CRM: OPEN → RETRYING，重新处理同一外部事实
  else 支付金额、时间或交易号不可信
    CRM->>CRM: PAYMENT_MISMATCH，不发权益
  else 映射和支付核验通过
    CRM->>CRM: 外部订单与内部订单一对一，创建/更新订单快照
    CRM->>CRM: 复用支付域确认 PAID，幂等写支付与 GRANT 权益
    CRM->>CRM: Raw PROCESSED，异常 RESOLVED
  end
  CRM-->>O: 返回处理状态、脱敏详情和补偿统计
```

> 当前默认 Mock/禁用真实接入；真实店铺尚未完成 Q11 授权联调。重复回调与主动拉单不能重复发权益，旧外部状态不能覆盖已支付事实；本流程不包含有赞真实退款同步。

### 4.4 预约、接诊、到院、服务与正式核销

```mermaid
sequenceDiagram
  actor M as 管家
  participant CRM as 预约核销权益服务/MySQL
  actor F as 机构前台
  actor O as 机构授权操作员

  M->>CRM: 选择客户、机构、时间及逐项目权益批次/计划次数
  CRM->>CRM: 校验客户范围、已支付快照、机构适用范围和权益有效期
  CRM->>CRM: 创建 PENDING_INSTITUTION；只记计划，不扣权益
  alt 机构拒绝或管家取消
    F->>CRM: reject 或 M 发起 cancel
    CRM->>CRM: REJECTED/CANCELED，追加预约历史
  else 正常履约
    F->>CRM: 本机构确认接诊
    CRM->>CRM: PENDING_INSTITUTION → CONFIRMED
    F->>CRM: 登记实际到院
    CRM->>CRM: CONFIRMED → CHECKED_IN
    alt 客户未到
      F->>CRM: 登记 no-show
      CRM->>CRM: NO_SHOW，不扣权益
    else 完成服务
      F->>CRM: 登记服务完成
      CRM->>CRM: CHECKED_IN → SERVICE_DONE
      O->>CRM: 选择逐项目批次、次数、服务时间与凭证，二次确认核销
      CRM->>CRM: 校验 OPERATOR、本机构映射、状态、客户/项目/机构和余额
      alt 越权、未到院、凭证缺失或余额不足
        CRM-->>O: 403/404/409/422，整批不写核销事实
      else 首次有效核销
        CRM->>CRM: 按序锁权益，同一事务写 POSTED 与逐项目 REDEEM 负流水
        CRM->>CRM: 更新余额、预约/订单净履约状态、审计与 Outbox
        CRM-->>O: 返回唯一正式核销；同键重试返回原结果
      end
    end
  end
```

> 管理员、管家和机构前台都不能直接正式核销。聊天或 AI 中“已做完服务”的陈述只是线索，不等于到院或 POSTED 事实。

### 4.6 退款申请、审批、执行与权益回收

```mermaid
sequenceDiagram
  actor M as 管家/退款申请人
  participant CRM as 退款订单权益服务/MySQL
  actor F as 财务审批与执行人
  participant P as 支付渠道/线下凭证

    CRM->>CRM: REJECTED/CANCELED，不写资金或权益事实
  else 异人审批通过
    F->>CRM: review=APPROVED
    CRM->>CRM: 拒绝自审，REQUESTED → APPROVED
    F->>CRM: 登记执行
    CRM->>CRM: APPROVED → PROCESSING，仍不更新最终资产

    end
  end
```

```mermaid
  participant S as MinIO/S3 私有桶
  participant V as ClamAV/格式校验
  actor D as 下载人

  U->>CRM: upload-init(分类、文件名、MIME、大小)
  CRM->>CRM: 校验角色、业务分类、机构范围、类型与大小上限
  CRM->>S: 创建未完成元数据并申请短期预签名 PUT
  S-->>U: 返回私有上传地址
  U->>S: 直接上传对象
  U->>CRM: upload-complete(fileId、ETag/hash)
  CRM->>S: 读取对象并核验 ETag、大小、MIME、SHA-256
  CRM->>V: 扫描实际对象并解析格式
  alt 病毒、格式或哈希异常
    V-->>CRM: FOUND/BLOCKED/校验失败
    CRM-->>U: 409/422，不可被业务引用或下载
  else 扫描通过
    V-->>CRM: CLEAN
    CRM->>S: 服务端写入封存对象并原子发布元数据
    CRM-->>U: CLEAN fileId，可在对应业务表单中引用
  end
  D->>CRM: 请求预览/下载
  CRM->>CRM: 重新校验当前业务权限、数据范围、分类和扫描状态
  alt 无权或对象不安全
    CRM-->>D: 403/404/409，并记录拒绝审计
  else 校验通过
    CRM->>S: 生成短期签名 GET
    S-->>D: 下载对象，CRM 记录下载审计
  end
```

> PAYMENT 通用凭证还要求支付确认权限、客户 ALL 范围及相应订单读取权限，机构账号不能使用该通用路径；EXPORT 使用专用生成链路。附件更换通过新版本，不覆盖旧引用。

### 7.3 知识资料发布、Dataset 同步、重试与停用

```mermaid
sequenceDiagram
  actor A as 知识发布管理员
  participant CRM as 知识发布与同步服务
  participant K as Outbox/Kafka/Inbox
  participant W as AI Worker
  participant D as Dify Dataset/Mock

  A->>CRM: 配置独立 Dataset ID/Key 并启用 syncEnabled
  A->>CRM: 选择 APPROVED 素材修订并显式发布
  CRM->>CRM: 校验发布权限、机构范围、CLEAN MATERIAL、UTF-8 TXT/Markdown 与 1 MiB 上限
  CRM->>K: 同事务创建 WAITING 映射/任务和最小 Outbox（仅 jobId/documentId）
  K->>CRM: 消费 knowledge.sync.requested.v1，严格校验并写 Inbox
  alt 重复或已停用资料的晚到事件
    CRM-->>K: 重复只确认；DISABLED 只记录 Inbox，不重新排队
  else 合法首次事件
    CRM->>CRM: WAITING → PENDING，事务成功后提交 offset
    CRM->>W: Worker 租约认领并请求同步/索引状态
    W->>D: 创建或按文本更新文档；外部调用不放入 DB 事务
    alt INDEXING
      D-->>W: 返回索引中
      W-->>CRM: 返回严格校验后的 INDEXING
      CRM->>CRM: 保留旧 ACTIVE 修订，继续有界轮询
    else AVAILABLE
      D-->>W: 返回可用结果
      W-->>CRM: 返回严格校验后的 AVAILABLE
      CRM->>CRM: 复核来源哈希，同事务将任务 SUCCEEDED、文档 ACTIVE 并切换当前修订
    else 临时失败
      CRM->>CRM: RETRY/FAILED，保存脱敏错误与退避
      A->>CRM: 对未停用 FAILED/RETRY 任务人工重试
      CRM->>CRM: 重置为 PENDING，attemptCount=0
    end
  end
  A->>CRM: 停用知识资料
  alt 已有远端 documentId
    CRM->>W: 先请求远端 disable
    W->>D: 停用远端文档
    D-->>W: 返回停用结果
    W-->>CRM: 成功后返回严格校验结果
    CRM->>CRM: 远端成功后才更新 DISABLED
  else 尚未创建远端文档
    CRM->>CRM: 直接停用等待中的资料
  end
  CRM->>CRM: DISABLED 为当前终态，晚到成功、重试或再次发布不能隐式启用
```

> 当前端到端验收使用真实 MySQL/Kafka/MinIO/ClamAV 与 **Mock Dataset**；真实 Dify、公开问答、多轮会话和 PDF/OCR 尚未验收或开放，Q19/Q20 未确认前不得启用真实同步。

### 8.3 Outbox → Kafka → Inbox 可靠事件

```mermaid
sequenceDiagram
  participant D as CRM 领域事务
  participant DB as MySQL Outbox/Inbox
  participant R as Outbox Relay
  participant K as Kafka
  participant C as 授权消费者
  actor O as 运维人员

  D->>DB: 同一事务提交业务事实 + Outbox(NEW) + 审计
  R->>DB: 原子批量认领，处理崩溃超时与有界退避
  R->>K: 按 aggregateId 分区发布最小事件信封
  K-->>R: acks=all
  R->>DB: 标记 SENT；若标记失败允许至少一次重发
  K->>C: 投递事件
  C->>C: 校验 Schema、版本、来源、权限和最小 payload
  C->>DB: 同事务插入唯一 Inbox + 更新允许的业务状态
  alt 重复 eventId
    DB-->>C: 唯一键命中，不重复执行业务动作
  else 首次合法事件
    DB-->>C: 提交 Inbox 与业务处理
  end
  C->>K: DB 事务成功后提交 offset
  alt 持续失败或事件非法
    C->>K: 有限重试后进入对应 DLQ，保留脱敏上下文
    K-->>O: 告警；经审批排障/回放并保留原因和操作人
  end
```

> Kafka 不参与支付金额或权益余额的最终事务判定。当前知识同步链路已验证真实 Broker + Inbox 幂等；不能把该结果外推为所有业务 Topic 均已有消费者或生产验收。

### 9.2 备份恢复、上线灰度与回滚

```mermaid
sequenceDiagram
  actor O as 运维/发布人员
  participant CI as 构建与安全门禁
  participant P as 生产环境
  participant BK as MySQL 备份/Binlog/对象备份
  actor A as 业务与安全验收人

  O->>CI: 构建候选包并执行全栈、漏洞、权限与核心账务验证
  alt 门禁未通过或 Q21/Q22 未放行
    CI-->>O: 阻断生产发布，不以安装成功替代上线验收
  else 获准发布
    O->>BK: 执行升级前数据库与对象备份并记录恢复点
    O->>P: 使用 expand/contract 迁移，部署应用并保持真实外部开关受控
    P-->>A: 执行登录、权限、支付/核销/退款抽样、回调与审计核验
    A->>P: 按批准范围灰度，观察错误率、Outbox、Kafka lag 和业务差异
    opt 需要回滚
      O->>P: 回滚应用或关闭功能开关；数据库不直接倒退
      O->>P: 必要时使用前向补偿迁移保护新事实
    end
  end
  opt 灾难恢复
    O->>BK: 选择全量备份、增量 Binlog 与一致对象快照
    BK-->>P: 恢复到隔离环境并校验表 checksum、对象哈希和账本对账
    A->>P: 验证真实登录、业务查询与私有下载
    P->>P: 再通过幂等 Outbox/Inbox 处理事件，不直接手改权益快照
  end
```

> 当前已有 Linux 单机安装基线和本机合成数据恢复演练，不代表生产高可用、真实公网 HTTPS、生产容量/渗透/恢复或灰度回滚已验收。RPO/RTO 仍是待批准目标。
