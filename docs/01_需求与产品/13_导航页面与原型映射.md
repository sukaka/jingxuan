## 2. 管家导航树
我的工作（dashboard/tasks/daily）；客户管理（customers/wecom）；服务履约（visits/redemptions/orders/refunds）；数据业绩（performance）。**同一个页面 key，后端返回和动作权限不同**。别用前端筛选隐藏全局结果。

## 3. 合作机构导航树
机构工作（dashboard/profile/changerequests）；客户履约（visits/redemptions/records）；财务结算（settlement）。在机构路由 `institutionId` 从服务端登录态解析；前端无法自由输入更换机构身份。

## 4. 页面组件复用约束
- 客户：`CustomerList`, `CustomerDrawer` 6 tab（概览、权益、核销、订单退款、服务记录、23字段档案），`CustomerMergeReview`, `OwnerTransfer`。
- 医院：`InstitutionList`, `InstitutionDrawer`（合作、资质、佣金、财务、商户一页纸、最近核销），`InstitutionProfileChange`, `ChangeApprovalBoard`。
- 订单：`OrderList`, `OrderCreate`, `OrderPaymentConfirm`, `EntitlementLedger`, `RedeemConfirm`, `RefundRequest`。
- 公共：`DataTable`, `EditableForm`, `DictionarySelect`, `DateTimeInput`, `FileUploader`, `AuditTimeline`, `PermissionGate`, `AsyncState`, `ErrorState`。

## 5. 迁移要求
1. 保留 V2.0 原型的主要信息层次与中文名称，不照搬 HTML 内联 JS 与本地 storage。
2. 新业务 API 先完成并有 mock 契约测试，前端采用强类型 SDK 请求真实后端。
3. 原型角色模拟只是交互示意，正式登录改为授权账号；预览的机构/客户/订单为虚构数据。
4. 还不存在于原型的“主管/商务/财务独立工作台”需要根据角色矩阵做专门权限和菜单设计，不能认为演示管理员已代表各角色。
5. 每个页面开发前生成独立“页面规格卡”：URL、角色、API、字段、按钮、校验、空态、错误态、权限、验收。
