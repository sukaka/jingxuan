## 标准的列表 CRUD 验收循环

1. 登录有权限角色 → 列表正确分页和筛选，点击目标行进入详情；存在记录级授权。
2. 点击编辑 → 表单回填所有可编辑字段并保留 `version`；非可编辑字段明确锁定/给原因。
3. 修改后保存 → 真实数据库已变更；刷新、退出重新登录后仍能查看正确新值。
4. 两个窗口并发修改同一记录 → 第一个成功，第二个 409 并提示刷新，不静默覆盖。
5. 删除/停用引用过的记录 → 历史订单等不丢失；停用后无法新选但旧数据可展示。
6. 没权限的人直调 API → 403/404；更换 ID 跨员工/机构访问也被后端拒绝。
7. 对姓名、电话、银行卡、佣金、证照等字段按差异日志追踪谁修改/审批，敏感旧值须脱敏存储。
8. 字典项重命名 → 旧记录按照 code 关联，在历史单据保留当时 label 或版本快照。

## 任务接手、转派、退回与完成工作流

实际 Flyway 迁移为 `V19__task_action_workflow.sql`；`V18__p2_order_type_snapshot.sql` 已由订单模块占用，不得把任务工作流写成 V18 或改写已占用迁移。

所有任务动作写接口均要求登录主体具有 `task:write`、有效 `X-CSRF-Token`、1–128 字符的 `Idempotency-Key` 和请求体中的当前 `version`。同一动作下同键同请求回放不重复改变状态或追加日志，同键不同请求、版本失配或非法状态转换返回 409；缺少幂等键、版本或必填原因返回 400。

| 动作接口 | 请求体必填字段 | 数据权限与状态规则 | 成功后的关键事实 |
|---|---|---|---|
| `POST /api/v1/tasks/{id}/claim` | `version` | 任务可见且当前为 `OPEN`；SELF 只能接手本人可见的同组任务池任务 | `OPEN → PROCESSING`；负责人为当前用户，写 `claimedAt` |
| `POST /api/v1/tasks/{id}/reassign` | `assigneeUserId`、`reason`、`version` | 仅 `MANAGER_LEAD`/`ADMIN`；任务为 `OPEN`/`PROCESSING`；目标是 ACTIVE 内部员工，主管只能转派给本组成员 | 状态为 `PROCESSING`；负责人和 `taskTeamId` 更新为目标员工及其团队，写 `claimedAt`；首次负责人不变 |
| `POST /api/v1/tasks/{id}/return` | `reason`、`version` | 当前负责人、同组主管或 ADMIN；仅 `PROCESSING` | `PROCESSING → OPEN`；当前负责人和 `claimedAt` 清空，保留任务团队及首次负责人 |
| `POST /api/v1/tasks/{id}/complete` | `version` | 当前负责人、同组主管或 ADMIN；仅 `PROCESSING` | `PROCESSING → DONE`；写 `completedAt`，当前负责人不变 |

- `reason` 在转派和退回时不得为空白，最长 500 字符。通用 `PATCH /api/v1/tasks/{id}` 只能修改普通资料字段，禁止传入 `status`；不得再用它驱动状态机。
- 旧 `PATCH /api/v1/tasks/{id}/assignee` 是兼容入口，内部统一走 `REASSIGN`，同样要求 `reason`、幂等键、CSRF 和 `version`，不允许绕过新工作流直接覆盖负责人。
- `GET /api/v1/tasks/{id}/actions` 要求 `task:read` 和任务可见范围，返回 `action/fromStatus/toStatus/fromAssigneeUserId/toAssigneeUserId/actorUserId/reason/createdAt` 等只追加日志；范围外返回 404。
- SELF 数据范围除本人任务外，还可见 `taskTeamId` 等于本人团队且 `assigneeUserId` 为空的任务池任务；其他团队不可见、不可接手。任务团队是任务快照，不随员工日后换组自动变化，只有明确转派才更新。
- Task 响应包含可空的 `assigneeUserId`，以及 `originalAssigneeUserId/taskTeamId/claimedAt/completedAt`。`originalAssigneeUserId` 创建后不可变；`crm_task_action_log` 由数据库触发器禁止 UPDATE/DELETE，历史和审计只能追加。
- 时间字段使用 UTC；页面展示时再按产品约定格式化，不以本地时间覆盖数据库事实。

## 禁止“万能修改接口”

不要提供一个 `PATCH /records/{table}/{id}` 允许前端传任意表名、字段名的通用修改接口。必须每个领域 DTO 白名单字段，后端校验权限和业务状态；财务和履约数据只能走命令式业务动作。任何快捷批量操作也应复用相同约束。
