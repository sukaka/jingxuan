## 强制原则

- 企业微信负责客户聊天，CRM 负责客户业务数据、辅助操作和 AI。
- 只使用企业微信官方能力，不使用个人微信 Hook、企业微信客户端注入、协议逆向或非官方采集。
- 普通客户联系消息不得由 CRM 后台任意冒充员工自动发送。
- 快捷话术、AI 回复必须由员工确认后，在企业微信当前聊天上下文发送。
- AI 不得自行生成订单金额、剩余次数、预约日期、退款金额等业务事实。
- `external_userid` 不是 CRM 客户主键，必须建立映射关系。
- 所有列表、话术、场景、机构、标签、渠道均可配置，禁止前端硬编码。
- 数据库结构变更必须提供 migration。
- 企业微信接口名称、参数和权限以开发时官方最新文档为准；不确定时必须核实，不允许猜接口。

## 推荐开发顺序

### P0
企业微信 OAuth、JS-SDK、聊天工具栏、当前客户识别、CRM 客户映射、客户资料、套餐剩余次数、快捷话术、预览编辑、当前会话发送。

### P1
AI 推荐回复、H5 卡片、个人收藏、机构/部门话术、发送统计。

### P2
会话内容存档、Kafka、消息入库、AI 意图识别、自动事件候选、回访/复购建议。

### P3
话术效果、AI 采纳率、预约/到院/复购转化分析。
