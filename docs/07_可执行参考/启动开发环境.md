# 启动参考环境（本地开发专用）

## 1. 前置
Docker Engine + Compose v2。复制 `.env.example` 为 `.env` 并替换开发密码，不提交 `.env` 到仓库。确认端口 3307、6380、29092、9000、9001 没有冲突。

## 2. 启动基础中间件
```bash
cd 07_可执行参考
cp .env.example .env
docker compose -f docker-compose.dev.yml --env-file .env up -d
docker compose -f docker-compose.dev.yml ps
```

如果 Kafka 在宿主机连 `localhost:29092`，容器内连接 `kafka:9092`。Kafka KRaft 单机仅用于本地，不用于高可用生产；首次启动失败应先核对镜像环境变量和 broker 日志，不要盲目删数据卷。

## 3. 建表参考（建议迁移成 Flyway V1__baseline.sql）
```bash
docker compose -f docker-compose.dev.yml exec -T mysql sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" medical_crm' < schema.mysql8.4.reference.sql
```
这条命令读取的是**参考全量蓝图**，真实开发应先从 P0-0 按模块拆为 Flyway 迁移，不建议每次运行全量参考 SQL 代替迁移。

## 4. 开发服务地址（正式骨架生成后）
- API `http://localhost:8080`（Swagger `/swagger-ui` 以项目实际配置为准）
- Vite Web `http://localhost:5173`
- Redis `localhost:6380`，Kafka `localhost:29092`
- MinIO Console `http://localhost:9001`

## 5. 检查
```
docker compose -f docker-compose.dev.yml config
docker compose -f docker-compose.dev.yml logs --tail=80 mysql kafka redis minio
```
部署正式系统之前必须更换环境密钥、关闭外部暴露端口、启用 TLS 和授权、分离 Kafka 和数据库、完善备份和监控。不要将本示例当作生产 Compose。
