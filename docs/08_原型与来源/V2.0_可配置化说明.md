# 医疗会员 CRM 交互原型 V2.0 — 可配置化与列表编辑说明

## 1. 本版目标

V2.0 重点解决 V1.9 中“很多列表数据固定、只能看不能改、下拉选项写死”的问题。

本版把系统数据分为两类：

1. **业务主数据 / 工作数据**：允许在权限范围内新增、修改、停用或删除误录记录。
2. **业务事实 / 审计数据**：已经支付、正式核销、成功退款、审批生效等事实不能直接覆盖，必须走冲正、退款、审批等流程。

## 2. 已增加修改能力的主要列表

- 客户中心：客户姓名、昵称、电话、城市、状态、来源、渠道、所属管家、关注项目、卡点、备注可修改。
- 每日跟进台账：沟通日期、方式、关注项目、预计金额、下次跟进、卡点、沟通内容可修改；误录可软删除。
- 回访任务：任务标题、类型、优先级、截止日期、负责人、状态、原因可修改。
- 产品子项目：分类、名称、价格、状态可修改；支持停用。
- 套餐规格：沿用版本化修改；已产生历史销售的套餐不物理删除，只下架。
- 合作达人 / 渠道：达人名称、推广渠道、商务、线索、订单、状态可修改；支持暂停合作。
- 预约：未完成预约可修改客户、项目、机构、日期、管家及预约状态。
- 订单：草稿订单可修改交易字段；已支付订单只能修改活动归属、批次及未形成正式核销前的履约机构。
- 退款申请：仅待审批状态可修改；审批后及成功退款锁定。
- 素材库：支持新增、修改、审核状态调整和下架。
- SKU 主数据：支持新增、修改、停用；阻止重复 SKU 编码。
- 机构中心：继续保留 V1.8/V1.9 的机构资料修改与机构端变更审批流程。

## 3. 新增“系统配置”

管理员左侧增加：

**系统配置 → 基础字典 / 列表配置**

当前可维护：

- 城市
- 机构业务类型
- 机构性质
- 商户等级
- 结算方式
- 客户状态
- 客户来源
- 客户渠道
- 订单类型
- 活动名称
- 沟通方式
- 任务类型
- 退款原因
- 素材类型

每个配置项支持：

- 新增
- 修改
- 启用 / 停用
- 删除

停用或删除配置项不会自动改写历史业务数据。

## 4. 配置项已接入业务表单

V2.0 中以下新建/修改表单优先读取系统配置，而不是继续把选项写死在代码中：

- 新建客户：来源、渠道、城市
- 修改客户：状态、来源、渠道、城市
- 新建订单：订单类型、所属活动
- 修改订单：订单类型、所属活动
- 新建跟进：沟通方式
- 修改跟进：沟通方式
- 新建任务 / 修改任务：任务类型
- 新建机构 / 修改机构：城市、业务类型、机构性质、等级、结算方式
- 新增 / 修改渠道：合作类型（博主/达人、分销、老带新）、推广渠道、结算方式；博主/达人为电汇月结，分销可选电汇月结或电汇每月两次，老带新固定结算规则未确认前留空。同步维护博主昵称、分佣比例、商务、真实姓名、联系方式、身份证、合作起止日期、收款账户/账号/开户行、合作状态与备注，敏感字段加密保存且审计不回显
- 退款申请 / 修改退款：退款原因
- 素材新增 / 修改：素材类型、城市

## 5. 为什么有些数据仍不能“随便修改”

以下数据属于已经发生的业务事实，系统故意限制直接编辑：

- 已支付订单的实付金额、购买次数、核心项目
- 已由合作机构确认的正式核销
- 已成功退款
- 已审批生效的机构敏感资料历史
- 已完成的服务预约

这类错误应该通过冲正、退款、审批、更正流水处理，而不是直接把旧数据覆盖掉，否则财务、权益余额、医院对账和业绩都会失真。

## 6. V2.0 原型限制

本版本仍是纯前端交互原型，数据保存在浏览器本地：

- 无真实数据库
- 无真实用户鉴权
- 无有赞真实接口
- 无企业微信真实会话存档
- 无合同/素材真实文件存储
- 无后端并发和审批权限校验

正式开发时，编辑权限、字段权限、软删除、版本号和审计日志必须由后端强制实现。
