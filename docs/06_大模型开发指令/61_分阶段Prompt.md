# 61 大模型分阶段开发 Prompt（按任务卡使用）

## 总调用方式
每轮任务只复制**一个任务卡**给开发模型，并告诉它仓库路径。不可直接说“帮我一次性把这个 CRM 完整做完”。每张卡必须附同一个尾部要求：**先读 `60_AGENTS.md`、需求状态机及 Qxx 未决清单；先列文件变更；写单测与集成测试；运行真实测试并提供结果；仅做本阶段，不编造第三方真实接口或历史数据。**

### P0-0 基础工程与开发环境
> 使用本包 `20_总体架构与ADR.md`, `30_MySQL建模规范与ER.md`, `40_REST_API规范.md`, `07_可执行参考/` 搭建 Java21/Spring Boot3.5.x + MySQL8.4 + Redis + Kafka/KRaft + Flyway + Vue3 TS + FastAPI Worker 空工程。设置统一错误结构/traceId/安全默认拒绝/CORS/CI/Testcontainers/容器依赖/健康检查。只产工程骨架和一张字典样表，不写假订单逻辑。验证 compose dependencies 和端口，记录版本锁。

### P0-1 客户与权限
> 从 V2.0 原型提取管理员/管家/机构三个菜单信息；按 `12_角色权限` 实现 sys_user/role/data_scope、客户23字段及独立生日积分、来源渠道、关联身份、查重候选/合并人工确认、归属转交审计；字典系统城市/客户来源/机构类型等支持 CRUD/停用并在表单生效。管家只能见本人客户。提供至少 C01-C04 的自动化权限/数据测试。

### P0-2 产品/套餐/SKU/机构适用
> 实现 project/package/version/package_project/sku/sku_institution 数据模型、接口和 Vue 页面，支持 3次/6次、选N项目、参与机构、编辑/停用、版本快照。未签定 Q01 的选择规则只能存模板不能自动发客户权益。加入 P01-P02 测试。

### P0-3 订单/支付/权益
> 实现订单草稿、订单行、支付确认、客户项目权益、权益流水与事务快照；金额整数分；支付回调幂等、事务 Outbox 统一。并发不能重复发权益。只提供可信确认接口，人工模拟支付要有授权和凭证；做到 O01/O02/E01/E02 测试。对 Q02 未确认金额分摊建立阻断。

### P0-4 预约/机构核销
> 实现管家预约指定机构→机构确认接诊→标记到院→服务完成→机构 POSTED 核销→MySQL同事务负权益流水。不能让管家直接最终核销。展示按机构、客户、项目的正式核销历史；支持冲正申请而不是改历史。覆盖 V01-V05 并发和跨机构权限测试。

### P0-5 机构主档、合同与资料变更审批
> 依据 V1.8-V1.9 以及 `14_页面表单` 完整实现机构业务类型/性质、SABC、线上线下点评佣金、月结/次卡次结、保证金/保投产、合同/资质文件、开户行账号税号（字段加密）。机构账户只能提交变更申请，按市场/财务路径审核，baseVersion 冲突暂停生效，保留不可覆盖历史。覆盖 H01-H04。

### P1-1 有赞真实适配准备
> 先写 `YouzanAdapter` 抽象/Mock 实现与脱敏fixtures，建立有赞订单入站原文/商品SKU映射/异常队列/补偿同步与幂等。缺官方账号授权前不写虚构真实 endpoint；提供供对接人员填写的字段映射表。真实接入待 Q11确认，先覆盖 O03/O04。

### P1-2 企业微信官方采集
> 先写 `WecomAdapter` + archive cursor/message ID DB、私有文件加密引用、消息队列、客户身份匹配/同意状态/采集监控；官方SDK待企业授权再联调。不得碰个人微信。覆盖 W01/W02，无同步时明确 data gap。

### P1-3 AI 管家/会话监管
> 根据 `43_AI智能管家设计` 写只读证据抽取 service、schema校验、异步AI job、人工确认入口、主管会话质量看板。恶意聊天不能控制系统；不能从 AI 自动扣次数、发款或正式核销。覆盖 AI01/AI02。

### P1-4 退款和医院结算
> 实现退款申请/审批/渠道成功回执/权益回收对应关系、医院月结与次卡次结批次/佣金快照/结算付款凭证、风险对账；费用基数待 Q04 Q05 Q06 确认则只做待核实账单不自动付款。覆盖 R01/R02。

### P2 数据运营/素材/导出/治理
> 实现机构商户一页纸与素材审批预览、城市/项目过滤、客户积分账本、管家商务业绩、活动大促看板、SKU规范和长尾质量统计、客户/订单/核销授权导出及审计。对 Q13 未签指标在UI标注口径待确认；覆盖 D01/X01/X02。

### P2-KB-1 Dify 知识问答适配与独立配置
> 只实现 AI Worker 知识问答内部契约、Mock/Dify Chatflow blocking Adapter、CRM 独立加密配置、管理员配置页和固定合成问题连接测试。真实 HTTP 默认由 FEATURE_REAL_DIFY 关闭，真实部署/模型/数据政策待 Q19，知识资料范围和保留期待 Q20。不得接入客户资料，不得实现 Dataset 同步、公开知识问答、多轮会话或业务写操作；不得将 Mock/模拟 HTTP 宣称为真实 Dify 联调。后续资料发布、正式问答和真实灰度分别另立阶段。

### P2-KB-2 资料发布与 Dataset 同步
> 分小步实现 Worker Dataset Adapter、已审核素材显式发布、版本映射、Outbox/Kafka/Inbox、索引状态、有界重试、停用和管理页面。只允许 APPROVED + CLEAN 的 UTF-8 TXT/Markdown，单文件最大 1 MiB；不得跨域直查 Mapper，不得改变素材审核历史。真实 HTTP 继续由 FEATURE_REAL_DIFY 和 Q19/Q20 阻断，开发只用合成文本/Mock/模拟 HTTP。公开问答、多轮会话、PDF/OCR 和真实灰度不属于本阶段；每个小步分别报告，未形成完整链路不得勾选完成。
