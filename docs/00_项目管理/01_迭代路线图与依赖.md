# 01 迭代路线图与依赖

> 顺序是依赖顺序，不是精确日历计划。每个阶段合并到 main 前必须通过 CI 与所列验收。

| 阶段 | 模块及关键任务 | 上游依赖 | 可运行成果/验收证据 |
|---|---|---|---|
| P0-0 | monorepo 骨架、配置、Swagger、Flyway、CI、测试容器、RBAC 基座 | 无 | compose 启动，健康检查，首个迁移 + 登录测试 |
| P0-1 | 员工/角色/组织/机构、字典、审计、客户及身份映射、标签、归属流水、查重候选 | P0-0 | 管家仅能查本人客户，动态字典真正改变表单值 |
| P0-2 | 项目、产品、套餐版本、销售规格、SKU、医院可用项目 | P0-1 | 一卡多规格、一规格多子项目、机构适用校验，销售快照 |
| P0-3 | 订单草稿、支付确认、权益发放、退款请求、权益账本与锁 | P0-2 | 重复支付仅发 1 次权益；并发不能超扣；金额对账 |
| P0-4 | 预约、医院接诊/到院/服务确认、机构正式核销与冲正 | P0-3 | 管家提交医院核销，医院确认后余额变化；不能跨院确认 |
| P0-5 | 机构合同/资质/收费/佣金、敏感字段变更审批和审计、合同文件 | P0-1 | 机构发起→市场/财务审核→生效→历史可查 |
| P1-1 | 有赞适配、订单映射、退款回调、人工异常台账、Outbox/Kafka | P0-3 | 同一外部订单回放100次不重发权益 |
| P1-2 | 企业微信客户联系 + 官方会话归档、游标追赶、未关联队列 | P0-1 | SDK 解密、重复消息去重、合法同意状态可追踪 |
| P1-3 | 每日跟进/客户待办、AI 证据提取和管家确认、会话监管 | P1-2 / P0-4 | 意图只生建议，不能自动改款项或核销 |
| P1-4 | 机构账单/结算、支付回单、基础财务对账 | P0-4 / P0-5 | 平台收款与医院收款严格分开，结算不重复 |
| P2 | 素材、活动大促、积分、业绩、SKU治理、经营报表、导出中心 | P1 | 定义数据血缘、报表口径、审计、导出脱敏 |
| P3 | 性能调优/多活规划/正式验收/上线 | P0–P2 | 备份恢复演练、安全验证、真实数据对账签字 |

## 每阶段任务规格
- 范围：对应的 API/数据表/页面/权限/事件/测试，用小型 PR 交付（理想每 PR 一个业务变化）。
- Definition of Ready：字段字典、状态转移、权限、业务口径、API、边界异常已定义；未确定部分使用可配置策略或挂起。
- Definition of Done：代码、Flyway 迁移、OpenAPI、单元测试、接口测试、前后端 E2E、审计日志、操作说明、性能回归、回滚方案。
- 每阶段输出 `CHANGELOG.md`、决策记录 `ADR`、测试报告（运行命令/结果）、已知问题。

## 必做跨服务契约演进
前端 API / Webhook / Kafka 事件都加显式 `version`；消费者先兼容再切换生产者；不要删除已投递事件的数据字段；要能重放、去重和告警。

## 优先风险
R1 原始套餐细项/公式不完整；R2 有赞权限未验证；R3 企微会话存档开通/客户同意；R4 收付款/医院结算费率算法未统一；R5 客户来源/归属与业绩关系。各风险指定业务负责人和截止判定日，未决不阻断独立模块，但阻断生产结算。
