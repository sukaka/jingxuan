# 00 项目总纲与范围

## 1. 愿景
建设覆盖“达人/渠道获客 → 客户建档 → 企业微信沟通 → 管家售卖/有赞订单 → 客户套餐权益 → 预约 → 合作机构接待到院 → 机构服务确认核销 → 退款/结算 → 管家、商务、运营业绩”的闭环 CRM。

## 2. 确定的业务事实（来自本次需求链路与 V2.0 原型）
- 客户可无手机号建档，手机号不是唯一主键；一个客户可有多个身份线索/企业微信关系。
- 保留原“客户信息表 23 字段”、日跟进、售卖、产品组合、子项目、医院、渠道、订单核销、管家/商务业绩原表语义，完整映射以原始字段和实际导出为准。
- 普通管家只看本人或授权范围客户；管理员具有公司级视图；机构操作员仅访问自己机构的数据。
- 管家先确定医院并发起预约，医院确认接诊、到院和服务；**医院授权操作员最终确认核销**；该确认后扣减项目权益。
- 套餐支持一个卡项多个销售规格、多个子项目及适用机构；已售历史须保存成交时的权益/定价快照。
- 有赞为待接真实订单来源，企微仅使用官方客户联系与合规会话存档；**不接入个人微信**。
- 管家与市场、财务、机构之间存在资料变更审批、客户归属日志、业务审计；V2.0 提供字典可配置和列表编辑交互参考。

## 3. 用户与角色
1) 老板/经营管理层：经营看板、全局查询、报表（敏感资料仍按授予权限）；2) 系统管理员：配置、组织、授权；3) 管家主管：团队跟进、会话服务质量、客户转交；4) 管家：我的客户、订单、预约、核销查询、退款申请；5) 运营：套餐、SKU、素材、活动；6) 市场/商务：机构、渠道、合同与佣金；7) 财务：支付、退款、机构结算、资金资料审核；8) 合作机构前台/运营/财务：本机构预约、到院、服务核销及限定的资料/对账信息。

## 4. 范围内与范围外
**范围内**：客户、会员/积分、机构、渠道、订单、支付/退款、服务权益与核销、预约/跟进、合同资质、审批、对账、业绩、产品/SKU/素材/活动、官方企微与有赞、AI 辅助、数据导出审计、动态字典。

**范围外（初期）**：医院 HIS 深度改造；个人微信消息获取；AI 自主确认支付/核销/退款；医疗诊断推荐；完整 ERP/财务总账；原型中虚构的数字自动变成真实经营指标；没有来源的历史消息回补。

## 5. 业务验收北极星
- 任一有效订单可追溯到客户、来源、售卖规格、付款状态、当时的权益配置、医院/预约、每条核销、退款与管家/商务归属。
- 任一项目可解释剩余可用次数：发放－已确认核销－成功退款回收＋合规调整。
- 核销不由管家独自确认；跨机构不能越权操作；重复回调不会重复发权益/扣次数。
- 主管能定位未回复、漏跟进、预约未接诊、到院未核销、异常订单；导出留审计。
- 机构敏感财务/合同变更经规定审批，前后值和审批轨迹可追踪。

## 6. 三类声明（所有文档必须使用）
- **[已确认]**：用户明确约定的流程与规则。
- **[设计建议]**：为开发可维护性选择的技术或默认方案，允许 ADR 变更。
- **[待业务确认]**：合同结算/退款算法、权限细项、运营数据口径等缺失事实，不能自行编造。

## 7. 非目标与成功路径
先做 P0 的客户/产品/订单/权益/预约/核销/退款主流程，再打通医院账号，随后有赞/企微、审批、AI 与经营分析。每阶段必须有回归测试、灰度和回滚方案；不能把“演示按钮可点”视为真正完成。
