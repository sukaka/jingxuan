# 24 部署、可观测性、备份与恢复

## 1. 环境规划
`dev`（开发自测，虚构数据）、`test`（自动化/性能/接口模拟）、`staging`（正式镜像/脱敏数据和部分真实接口沙箱）、`prod`（用户数据）。各环境数据库/Redis/Kafka/对象存储/企业微信凭据隔离；绝不把生产库复制给开发环境而不脱敏。

## 2. Compose → 生产演进
开发 Compose 单机 MySQL+Redis+Kafka KRaft+MinIO；生产至少分离数据库与应用，支持数据库备份/binlog 与高可用，Kafka topic 正式复制，Redis 独立、对象存储数据冗余。是否用 K8s 依据团队运维能力，不作为首期完成前提。

`infra/production/` 提供 x86_64 Linux 离线安装包：独立生产 profile、非 root 应用镜像、Caddy HTTPS、内外网络隔离、密钥生成、管理员初始化、升级前数据库备份及本机 ClamAV 代理。`./scripts/build-installer.sh` 默认先执行全栈验证，再构建镜像和压缩包。正式安装需要系统与文件两个域名；不包含开发账号、生产密钥或真实供应商授权。生产种子补齐订单类型、机构业务类型/性质/等级和结算方式等系统参考代码，重复执行不覆盖运营已修改的显示名、排序和启停状态；不包含城市、客户、机构或订单演示数据。这是单机部署基线，不替代下述高可用和生产验收。ClamAV 仅开放必要的出站更新通道访问 `database.clamav.net`，不开放宿主机端口；严格离线环境必须另行导入新病毒库。

## 3. 配置与密钥
通过环境变量/Secret 注入 `DB_URL`, `DB_USER`, `DB_PASSWORD`, `REDIS_URL`, `KAFKA_BOOTSTRAP_SERVERS`, `S3_*`, `WECOM_*`, `YOUZAN_*`, `AI_PROVIDER_KEY`；严禁将私钥写入配置仓库；企业微信 RSA 私钥使用独立权限和轮换计划。

## 4. 日志/指标/追踪
核心指标：HTTP RPS/5xx/p95/p99；MySQL 活跃连接/锁等待/死锁/慢 SQL；Redis 命中/驱逐；Kafka consumer lag/DLQ；Outbox 最老未投递秒数；有赞同步最后成功、商品映射失败；企微 `seq` 连续性/最后成功采集/解密失败；AI 超时/无证据结果占比；扣减失败、幂等冲突、日终权益对账差异；医院待接诊/待核销积压；资质预警未处理。

## 5. 备份与恢复
- MySQL 全量+增量/binlog，执行至少月度抽样恢复验证；对象存储版本化和备份；Kafka 事件不是 MySQL 的数据库备份。
- 建议起始目标：RPO <= 15min，RTO <= 4h（**设计建议，不是已批准 SLA**）；正式指标需按成本/风险批准。
- 恢复顺序：先恢复 MySQL 事务点和对象存储一致快照，再处理 Outbox/Inbox 与 Kafka 重放；只允许通过幂等机制恢复事件，不得直接改权益快照。
- 用 3 类事故演练：误删字典、单独 MySQL 节点故障、外部 API 积压导致同步滞后。

## 6. 上线与回滚
- Flyway forward-only；变更采取 expand/contract，避免上线时删旧列、改含义。
- 流量灰度：功能开关控制有赞真实回调、企微采集、AI 自动建议，不允许 AI 自动交易生效。
- 上线核验：业务真实账务抽样、错误率、业务事件重复率、权限回归、外部回调签名、审计与隐私检查。回滚应用不等于数据库回滚，必要时写补偿迁移。

## 7. 开发环境快速运行参考
`07_可执行参考/docker-compose.dev.yml` 提供容器依赖和独立命名空间；第一次启动前改 `.env`；生产不得直接使用开发 Compose（不含 TLS、HA、安全网络分区）。
