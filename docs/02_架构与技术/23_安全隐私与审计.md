# 23 安全、隐私、合规与审计

## 威胁模型及安全边界
CRM 存储客户联系方式、消费项目、医疗服务项目/到院信息、部分聊天内容、退款和银行账户，敏感程度高。角色越权、内部人员批量导出、机构跨机构查询、审批绕过、Webhooks 伪造、日志意外明文、AI 越权召回、订单核销竞态是优先威胁。

## 控制清单
1. **认证**：短会话、MFA、强密码、失败锁定、机构独立账号、员工离职撤权、审计登录设备和 IP。
2. **授权**：RBAC+ABAC；后端按 `tenant_id/team/owner_staff_id/institution_id` 加数据范围；列级掩码，文件与导出签名校验；拒绝未授权字段修改。
3. **网络**：全站 HTTPS，服务间 TLS/专网；Redis/MySQL/Kafka 不暴露公网；入站 Webhook 做签名、时间窗口、防重放、IP 白名单（仅辅助）。
4. **数据加密**：库磁盘/备份加密，银行账号、手机号及健康相关敏感字段可做应用层加密/脱敏/密钥轮换；数据库管理凭据用 secret manager；绝不提交 `.env` 实密钥。
5. **审计**：登录、导出、查看高敏感聊天/银行数据、转交、合并、核销/冲正、退款、机构变更审批、权限变更均保存 before/after、actor、原因、traceId。日志只追加/不可由业务用户编辑；防篡改归档。
6. **文件**：私有桶、上传病毒/内容检查、后端生成短时预签名 URL、PDF/图片预览水印（按权限）、下载流水、文件版本/到期清理。
7. **聊天合规**：仅企业微信官方开通权限范围和满足同意条件的聊天归档；客户撤回授权或停止服务后的处理依照制度配置。明确不采集个人微信。
8. **AI**：敏感字段最小化，模型输入遮盖不必要个人资料；分层访问聊天上下文；提示注入仅为不可信内容，不允许让 AI 执行支付/核销/退款；记录模型版本和评估，但不留出超期原始明文。
9. **漏洞治理**：依赖扫描、SAST/DAST、OWASP Top 10、参数化 SQL、文件白名单/路径安全、CORS/CSP/CSRF/XSS 防护、secret scanning。
10. **合规确认**：健康数据、财务信息、企业微信存档、数据保留及跨境模型传输须由组织法务/安全确认具体处理依据和告知同意方式；开发文档不代替法务意见。

## 事故演练用例
- 机构账号修改 `institutionId` 获取别院核销 → 服务端403，安全告警。
- 管家调用导出 API 读取全量客户 → 403，记录拒绝事件。
- 企业微信存档失去权限 → 采集暂停告警，不把“0条聊天”解释为客户未联系。
- 支付通知签名错误 → 记录拒绝，不建单、不发权益。
- 关键敏感资料审批人在自己申请中出现 → 拒绝并审计。
- 密钥泄露 → 轮换影响范围评估，撤销旧凭证，回溯访问流水。

## 保留与删除
制定按数据类别和处理目的的保留期：一般客户资料、聊天存档、合同、支付凭证、登录审计、操作审计分别配置；到期作清理/匿名化，涉及财务法定保存按适用法律另行确认。删除客户不能物理删除有法律或账务留存义务的订单/核销事实。
