# 44 合同/资质/支付凭证/素材文件及医院协作

## 1. 文件生命周期
客户端向 API 申请 `upload-init` → 服务端校验角色/文件类型/最大大小，创建未完成记录、预签名 PUT URL → 客户端上传私有对象 → `upload-complete` 验证对象ETag/hash/大小 → 防病毒扫描/格式解析 → `CLEAN` 后允许引用。所有读取/下载必须重验业务权限并生成短期签名URL；上传者无权使未批准的素材自动公开。

## 2. 对象分组（独立桶或同桶安全前缀）
- `contracts/` 机构合同/续签 PDF：合同编号版本、审核人、签署与到期、不可覆盖历史版；
- `qualifications/` 医疗资质、营业执照；仅市场/法务等授权范围；
- `payments/` 客户支付/银行回单，财务权限；
- `redemptions/` 机构签收/履约凭证，与核销ID绑定；
- `materials/` 经审核可给管家看的机构简介/医生/设备/案例，外发单独授权；
- `wecom/` 合法归档聊天媒体，极高隐私级别；
- `exports/` 临时导出短生命周期和水印。

## 3. 机构账号流程
院方账号仅可以查看分配到该医院的预约，执行接诊/到院/服务/核销；发生服务异常可发起驳回或更正申请。医院可提交本院资料变更请求，但合同、佣金、保证金、银行账号、税号等审批前不能修改正式值。单一医院可以有前台、运营、财务多个细分角色。

## 4. 医院接口适配
第一版使用院方 Web 界面履约，不依赖每家医院 HIS。未来如医院提供 API，建立 `InstitutionAdapter`：预约回执、到院签收、服务确认、退改操作；外部调用必须带 partnerId、签名/令牌、幂等键与审计，不能直接把外部 payload 写进权益账本。正式核销确认权限和 API 凭据由同一医院授权链路限定。

## 5. 文件审计与保留
文件元数据记录 `object_key`, `sha256`, `mime_type`, `size`, `classification`, `uploader`, `scanStatus`, `expires_at`, `version`; 附件更换通过新版本，不覆盖旧文件引用。银行账户的申请审批历史仅保存脱敏审计可见值，机密原值加密；前端一页纸永不含银行账号和税号。

### 文件安全补充（0.1.1）

PAYMENT 凭证尚未绑定客户或订单；访问、上传及引用要求支付确认权限和客户 ALL 数据范围，读取另需订单读取权限，机构账号不得使用该通用凭证路径；有机构归属时仍须满足机构权限。上传对象经完整校验和病毒扫描后，由服务端将扫描内容写入新的封存对象并原子发布；旧 CLEAN 对象首次使用时重新校验、扫描并封存，失败时拒绝访问。EXPORT 保持其专用生成链路。接口和事件签名无变化。
