# 41 企业微信字段映射与交接（官方客户联系 / Mock 会话存档）

## 0. 官方客户联系字段（V12）

以下字段已按企业微信官方 `externalcontact/batch/get_by_user` 与 `externalcontact/get` 文档映射，不再把 Mock 字段当官方字段目录：

| 官方字段 | CRM 字段 | 规则 |
|---|---|---|
| `external_contact.external_userid` | `external_userid` | 与 corpId、staff_user_id 共同定位跟进关系，不是自然人唯一 ID |
| `external_contact.name/avatar/type/gender/unionid` | `name/avatar/contact_type/gender/unionid` | 可空字段保持为空；unionid 不自动合并 CRM 客户 |
| `follow_info.userid` / `follow_user.userid` | `crm_wecom_staff_account.wecom_userid` | 必须映射到启用的 CRM staff_user_id |
| `remark/description/createtime` | `remark/description/follow_created_at` | 属于具体跟进成员，不是全企业共享值 |
| `add_way/state` | `add_way/channel_state` | 分别为官方来源编码和企业渠道参数 |
| `tag_id` 或 `tags` | `tag_snapshot_json` | 批量接口只有企业/规则组标签 ID；单客户详情保留标签快照 |
| 回调 `del_external_contact` | `follow_status=DELETED_BY_STAFF` | 只关闭关系，不物理删除历史 |
| 回调 `del_follow_user` | `follow_status=DELETED_BY_CUSTOMER` | 不影响其他成员跟进关系 |

`consent_status/consent_evidence_ref` 仍仅用于会话存档，官方客户资料响应不会自动产生 GRANTED。`customer_id` 继续走人工确认，与官方客户资料同步解耦。

## 1. 边界与证据分级

下文仅描述会话存档 Mock fixture、内部 DTO 与处理规则，不是会话存档官方字段目录。Q10 未确认，`FEATURE_REAL_WECOM=false`，真实存档 SDK 保持禁用；官方客户联系 HTTP 适配已独立实现。个人微信、非官方 hook 和模拟登录一律禁止。

- `MOCK-CORP-001`、`MOCK_ARCHIVE` 和 `mock://consent/*` 都是开发占位，不是实际企业、覆盖范围或客户同意证据。
- Mock 的 GRANTED/REVOKED 只用于验证状态机，不能据此宣称企业已开通存档或客户已授权。
- `/api/v1/integrations/wecom/**` 是 CRM 内部管理接口，不是官方 endpoint。

## 2. Mock 字段 → 内部字段/用途

| Mock 字段 | 内部映射/用途 | 规则与边界 |
|---|---|---|
| `msgId` | `crm_wecom_message.msg_id` | 与 `corpId` 唯一；重复只计 `duplicates`，不重复写密文或事件 |
| `seq` | `archiveSeq`、游标 `lastSeq`/`committedSeq` | 必须严格递增；回放不能超过已确认成功位置，失败不推进成功游标 |
| `externalUserid` | 联系人/消息 `external_userid` | 外部身份，不是自然人或 CRM 客户 ID；未匹配须人工确认 |
| `staffUserId` | 联系人/消息 `staff_user_id`、归档成员覆盖 | 必须同时满足当前员工/团队范围与归档成员 enabled，不是任意员工可采集 |
| `conversationId` | 消息/事件 `conversationId` | 可空 metadata，不是公开会话地址 |
| `messageType` | 消息/内容视图 `messageType` | 例如 TEXT；不得据此自动执行交易或核销 |
| `senderType` | 消息 `senderType` | `EMPLOYEE/CUSTOMER`，用于区分员工与客户发言 |
| `sentAt` | 消息/事件 `sentAt` | 保留实际发送时间，不能用接收时间替代 |
| `text` | AES 加密私有对象；授权 content 接口的 `content` | 事件/列表不传正文；每次读取须同意/覆盖/范围复查和摘要校验 |
| `consentStatus` | 联系人 `consentStatus`、消息 `consentSnapshot/currentConsentStatus` | `PENDING/GRANTED/REVOKED`；Mock 状态不是实际授权，采集和读取均复查 |
| `consentEvidenceRef` | 联系人/消息同意证据引用 | 仅存引用，不存敏感证据正文；Mock URI 不是实际证明 |
| `customerId` | 人工链接后的 CRM 客户 ID | 未匹配为 null；只有当前可见客户可链接，已确认不得改绑 |
| `version` | 联系人乐观锁 | 人工链接必传当前 version，失配 409；同步接触状态更新也检查 version |
| `reason` | 人工 `linkReason` | 必填身份匹配理由和证据，不能只按手机号/昵称合并 |
| `contentObjectKey` | 私有 MinIO 对象引用 | `wecom/{tenantId}/{corpId}/{uuid}.json.enc`，不是公开 URL，不是正文 |
| `contentSha256` | 私有对象密文摘要 | 正文读取前校验，防篡改/错读；不进入 Outbox payload |
| `lastSuccessAt/lastAttemptAt` | 游标最近成功/尝试时间 | 无游标时均可为 null，状态为 NEVER_SYNCED |
| `dataGap/gapReason` | 当前覆盖状态与脱敏原因 | 无游标或 committedSeq=0 时 DATA_GAP，不能表述为无沟通 |
| `activeGaps/historicalGaps` | OPEN 与已解决缺口计数 | 解决后保留历史，不删除或覆盖缺口事实 |

## 3. 当前 fixture 与预期

| 外部身份/消息 | Mock 同意与覆盖 | 预期处理 |
|---|---|---|
| `WECOM-EXT-1010` / `WECOM-MSG-001` | GRANTED，成员已覆盖 | 可加密归档；客户仍需人工链接，链接前可为 UNMATCHED |
| `WECOM-EXT-UNMATCHED` / `WECOM-MSG-002` | GRANTED，但无 CRM 客户链接 | 元数据可保留为 UNMATCHED；人工确认后才关联客户并改 STORED |
| `WECOM-EXT-REVOKED` / `WECOM-MSG-003` | REVOKED | 跳过正文，记录 `CONSENT_NOT_GRANTED` 缺口，不得把内容存入 MinIO |

Mock 的 `mock://consent/1010`、`mock://consent/unmatched`、`mock://consent/revoked` 只用于演示证据引用格式，不是有效合同、授权书或客户同意。

## 4. W01：msgId 与游标验收

- `corpId + msgId` 和 `corpId + archiveSeq` 均有唯一约束；重复拉取不会生成第二条消息。
- `seq` 必须严格递增。重复区间可重放并去重，但不能把旧状态覆盖到较新区间。
- cursor 缺省取已保存成功位置；传入 cursor 超过已确认成功位置返回 400。
- `lastSeq` 表示已确认覆盖区间末尾。拉取或写对象失败时只记录失败/缺口，不能把该区间标记为成功。
- 同步返回的 `received/stored/duplicates/skipped/lastSeq/hasMore/dataGap` 必须分别解释：重复不是 stored，未同意/未覆盖是 skipped 和 gap，不是 duplicates。

## 5. W02：DATA_GAP 与空态验收

- 无游标：`NEVER_SYNCED + lastSeq=0 + dataGap=true + 尚未采集，无法判断沟通情况`。
- `committedSeq=0` 同样表示没有已确认覆盖区间，而不是没有沟通。
- `CONSENT_NOT_GRANTED`：同意未确认或撤回，不存正文。
- `MEMBER_NOT_COVERED`：成员不在覆盖范围，不存正文。
- `COLLECTOR_ERROR`：拉取/处理失败，成功游标不推进；可重试并保留历史。
- `activeGaps` 为 OPEN，`historicalGaps` 为 RESOLVED；`messageCount` 受数据范围限制，不能据此推断员工未沟通。

## 6. 人工身份、同意与正文读取

- 人工链接：`customerId + version + reason`，联系人和客户均须在范围内；已确认链接不得改绑，同客户同理由可安全重放。
- 采集检查：`consentSnapshot=GRANTED`、当前 `consentStatus=GRANTED`、归档成员 enabled、客户/员工范围全部满足。
- 每次列表与正文读取都重新检查上述条件，不能只凭采集时同意长期放行。
- 正文只在 `/messages/{id}/content` 返回：先校验私有密文 SHA-256，再 AES 解密并记录读取审计；不通过预签名永久 URL 公开。
- Outbox 仅包含 `messageRef/corpId/msgId/archiveSeq/conversationId/customerId/contentObjectKey/sentAt` 和缺口 metadata，不包含正文、密钥或 consumer 承诺。

## 7. Q10 真实开通与交接清单

| 确认项 | 对方必须提供/确认 | 当前 Mock 不能决定 |
|---|---|---|
| 企业与存档资质 | 企业主体、官方应用、会话存档开通状态、计费与可用环境 | `MOCK-CORP-001` 不代表真实资质或官方授权 |
| 可采成员范围 | 实际被存档员工名单、启用/停用/离职变更、管理员审批证据 | Mock enabled 列表不能替代企业审批 |
| 客户同意 | 同意文本/流程、可验证证据、版本、时间、撤回状态及覆盖人群 | `mock://consent/*` 不是合法同意证明 |
| 官方 SDK 与环境 | 官方 SDK 版本、依赖、回调域名/网络、企业凭证、沙箱与生产配置 | Mock Adapter 没有官方 SDK 环境或密钥 |
| 私钥与凭证托管 | 私钥生成/托管/轮换/吊销、访问审计、泄露应急与责任人 | 不在文档/仓库保存真实私钥或 secret |
| 游标与限流 | seq 语义、分页大小、QPS、游标有效期、限流响应、重试与补采窗口 | Mock limit=1–100、固定 seq 不是官方限制 |
| 媒体与内容权限 | 文本/图片/文件/语音等媒体权限、大小、格式、解密与下载审计 | 当前只处理 Mock TEXT，不推断官方媒体权限 |
| 字段与状态字典 | 官方消息类型、ID、发送者/会话字段、时间/时区、撤回类型与错误码 | Mock 字段名不能当官方字典 |
| 保存/删除/撤回流程 | 保存期限、到期删除、撤回同意后的停采/读取/删除/审计及法务批准 | 当前 REVOKED 阻断读取不等于完整法定删除流程 |
| 联调与验收 | 官方沙箱企业、授权联系人、测试消息、故障升级、回滚方案和上线检查单 | 当前只有本地 fixture，未进行真实联调 |

### Q10 放行门槛

真实 Adapter、官方字段映射、资质/成员/同意证据、密钥与 SDK 审查、沙箱验证及删除/回滚方案全部完成后，才允许评审功能开关。当前 `FEATURE_REAL_WECOM=false` 必须保持；仅改开关不代表完成官方接入，也不得以 Mock 结果宣称生产企微已联通。
