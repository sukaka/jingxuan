# 42 有赞订单、支付与同步适配（P1-1 Mock + P1-1R 真实接入预建）

## 1. 边界与禁用状态

当前交付包含 **MockYouzanAdapter、内部适配 API、映射、补偿与异常队列**，以及 **P1-1R 真实店铺配置、Token/订单客户端、官方消息和同步任务预建**。真实店铺仍未授权联调，不能宣称生产有赞已接通。

- Q11（店铺类型、授权、订单/退款订阅、限流与字段规则）未确认，`FEATURE_REAL_YOUZAN` 默认仍为 `false`。具备 `integration:runtime:manage` 的管理员可在有赞页面保存当前租户的全局开关，覆盖环境默认值并即时生效；保存动作写审计，但不代表 Q11 已验收。
- 本地 `local` profile 使用 Mock fixture；真实调用还需已保存店铺配置并启用 `syncEnabled`。不满足条件时使用 `DisabledYouzanAdapter`，真实拉取返回 `PENDING_BUSINESS_RULE`/422。
- `RealYouzanAdapter` 使用官方 `/auth/token`、`youzan.trades.sold.get/4.0.2` 和集中配置的订单详情版本（默认 `4.0.2`）。`YOUZAN_API_BASE_URL` 只允许服务端受控配置，用于模拟联调，不开放前端任意地址。
- 店铺 `clientSecret/accessToken/refreshToken` 使用 AES-GCM 密文保存；API 只返回 `secretConfigured` 和连接状态，不回显密钥或 Token。编辑配置后旧 Token 失效。
- 官方消息入口为 `POST /api/v1/webhooks/youzan/official`，使用 `Client-Id/Event-Type/Event-Sign`，与 `/api/v1/webhooks/youzan` 的开发 Mock HMAC 完全分离。官方测试消息不进入订单处理。
- 官方消息验签后先落库，30 秒后查询订单详情，再进入既有映射和支付链路；失败按 60 秒重试。消息本身不作为资金到账凭证。
- 本阶段不交付退款同步，不宣称业务 Kafka consumer、Inbox 消费去重或真实店铺联调已完成。

字段级 fixture 映射和真实对接交接清单见 [42_有赞字段映射与交接.md](42_有赞字段映射与交接.md)。

## 2. 当前调用链

```text
内部管理 API / Mock webhook
  → YouzanManagementService / YouzanEventService
  → YouzanAdapterRouter
      ├─ local：MockYouzanAdapter（固定脱敏 fixture）
      └─ 其他或真实拉取：DisabledYouzanAdapter（禁用）
  → 原始事件 + SKU/客户/订单映射 + 异常队列
  → 订单与支付领域服务（不是把 Adapter DTO 当订单实体）
  → Outbox relay（仅发布侧）
```

原始 JSON 经过递归脱敏后保存 `payload_masked_json`，完整原文使用 AES 保存 `payload_cipher`。API 仅向具备 `integration:youzan:manage` 的管理员返回 `payloadMaskedJson` 脱敏文本，普通 `order:read` 用户该字段为 null；绝不返回 `payload_cipher` 或原始明文。Raw 处理状态与内部订单字段分开呈现，前端原始详情仅供管理员排障并默认折叠。

## 3. 实际内部 API

| 方法与路径 | 权限与用途 | 关键结果/错误 |
|---|---|---|
| `GET/POST /integrations/youzan/shops` | `integration:youzan:manage`；查询/保存真实店铺授权，写操作需 CSRF + Idempotency-Key | secret 不回显；新建缺 secret 400；更新 version 冲突 409 |
| `POST /integrations/youzan/shops/{shopId}/test` | 同上；测试 Token 获取和订单列表权限 | 功能开关关闭时 422，不伪造连接成功 |
| `GET/PUT /integrations/youzan/shops/{shopId}/sync-policy` | 同上；首次导入开始时间、增量频率、重叠秒数、页大小和自动开关 | 页大小 1–100；店铺不存在 404 |
| `GET /integrations/youzan/sync-jobs` | 同上；按店铺分页查询 FULL/INCREMENTAL/RECONCILE 任务及统计 | RUNNING/SUCCEEDED/PARTIAL/FAILED；不展示密钥 |
| `POST /webhooks/youzan/official` | 官方 `Event-Sign`；精确匿名路径，不要求 CRM Cookie/CSRF | 202 仅表示验签接收；未知店铺/签名错误 401；测试消息不处理 |
| `GET /integrations/youzan/orders` | `order:read`；按外部订单最新 Raw 分页，授权范围内可含未映射/未匹配记录 | 无内部订单时 mapId/orderId/orderStatus/paidFen/verificationMethod 为空；仅 manage 返回脱敏原文，普通只读为 null；越权 404 |

| `GET /integrations/youzan/reconcile-report` | `order:read`；同步摘要 | 返回总事件数、内部映射数、OPEN 异常数、最近成功时间、当日原始事件数和活动订单数；当日统计不等于支付订单数 |
| `GET /integrations/youzan/sync-issues` | `order:read`；异常分页 | 详情均脱敏 |
| `POST /integrations/youzan/sync-issues/{id}/retry` | `campaign:write` + CSRF + Idempotency-Key；重试未解决异常 | 不存在 404；RESOLVED/DEAD 409 |
| `GET /integrations/youzan/sku-mappings` | `order:read`；查询 SKU 映射 | 200 |

| `GET /integrations/youzan/customer-links` | `order:read`；查询客户映射 | 200 |

### 3.1 真实同步策略与游标

- 首次同步按 `start_created/end_created`，长时间历史按最多 90 天的内部窗口分段；订单列表使用 `page_no/page_size`，单页最多 100，页码最多 100。
- 自动增量按 `start_update/end_update`，策略可配置 60–86400 秒间隔和 0–3600 秒重叠。`next_run_at` 支持 Web 直接修改下次执行时间，保存后无需重启；每次认领后按间隔推进，过去时间视为立即执行。窗口与页码 JSON 最长 2048 字符，和 Mock 数字游标兼容存储。
- 真实列表返回订单号后逐单调用详情接口，再转换为内部事件。元字符串金额使用 `BigDecimal` 精确转整数分；客户键为 `yz_open_id`，SKU 键为 `item_id:sku_id`。
- 每次手动/自动执行记录 `crm_youzan_sync_job`，只有接收、处理、重复和异常统计；`PARTIAL` 不等于全部成功。数据库策略版本和任务租约用于避免同店铺并发调度。
- `payload_cipher` 保存内部标准事件，`provider_payload_cipher` 保存官方原始报文；公开 `payloadMaskedJson` 由原始脱敏字段与内部标准字段合并，不包含密文。

### 3.2 安全与可靠性加固（V14）

- `youzan.sync.completed.v1` 的 Outbox `event_id` 使用 `shopId + SHA-256(nextCursor)`，不再把可变长 JSON 游标直接拼入事件键；相同游标保持确定性幂等。
- 订单列表到第 100 页且仍有数据时强制将当前时间窗二分续跑；不能继续细分时进入异常，禁止静默漏单。
- 官方消息重复到达但尚未 `PROCESSED` 时会重新安排详情查询；启动和每 30 秒扫描超时 `RECEIVED/RETRY`，覆盖重启丢失的内存定时任务。
- 明确 Token 失效时按店铺单飞强制刷新并仅重试一次；店铺级调用间隔默认 100ms，429 最多三次调用并支持 `Retry-After`，不无限退避。
- `crm_youzan_shop_config` 新增店铺租约；任务开始获取、每页续期、成功/失败均释放。过期 RUNNING 任务标 FAILED 并释放过期租约，后续从持久化游标续跑。
- 官方匿名回调限制 1MB 和最多 64 层嵌套，Content-Length 超限直接 413；解析层继续兜底 chunked 或伪报长度。
- 脱敏覆盖导购/销售员手机号、姓名、员工 ID、外部平台身份、收货电话和留言备注；系统操作员按当前租户选择 ACTIVE ADMIN，不再固定用户 1。
- `sync/reconcile` 改为 `integration:youzan:manage`，普通 BUSINESS 角色不能通过同步间接触发支付确认。

## 4. Mock webhook 安全约定

以下仅是 **开发 Mock 协议**，不是有赞官方签名规范：

- 请求头：`X-Youzan-Mock-Signature`、`X-Youzan-Mock-Timestamp`（Unix 秒）。
- 签名：`hex(HmacSHA256(timestamp + rawBody))`，密钥来自 Mock 环境配置。
- 时间窗：当前时间与 timestamp 的绝对偏差不得超过 300 秒；缺签名/时间、伪造或过期均返回 401。
- 必须对原始请求体验签，不能用重新序列化后的 JSON 代替原文。验签通过后才解析事件、落 raw 并异步处理。
- 密钥不得写入文档、日志、fixture、异常消息或仓库。不得在交接材料中打印环境实际密钥。
- webhook 允许匿名调用但依赖 Mock 签名，不是安全豁免；真实回调安全规则仍待 Q11 确认。

## 5. 处理状态与可信支付

### 5.1 原始事件

- 验签通过首次入库：`RECEIVED`；同 `shopId + eventId` 已存在则按重复事件返回。
- 映射和处理成功：`PROCESSED`，同时保存内部 `orderId`。
- 可分类失败：`MAPPING_FAILED`、`CUSTOMER_UNRESOLVED`、`PAYMENT_MISMATCH`，并创建/更新 OPEN 异常。
- 其他可重试失败：`RETRY`，记录 `nextRetryAt`；schema 的 `DEAD_LETTER` 不代表当前已有自动死信 consumer。

### 5.2 异常队列

`OPEN → RETRYING → RESOLVED`。只有 OPEN/RETRYING 可人工重试；RESOLVED/DEAD 不可重试，返回 409。重试后仍失败会保留异常和脱敏原因，不伪造成功。

### 5.3 订单与支付

- 外部订单先经 SKU 映射、客户人工链接和订单快照规则校验；未匹配不得创建可用权益。
- `ORDER_PAID` 必须有交易号、支付时间、正整数分金额，且金额等于内部应付金额，否则 `PAYMENT_MISMATCH`。
- 新订单先 DRAFT；满足支付条件后提交 PENDING_PAYMENT，再由支付域确认 PAID 并发放权益。
- 支付回调使用 `paymentChannel=YOUZAN`、`verificationMethod=PROVIDER_CALLBACK`；人工支付仍保留 `MANUAL_REVIEW`。
- `externalUpdatedAt` 不晚于已处理版本时按重复/旧版本处理，不用旧状态覆盖新事实。已支付历史不可由普通同步覆盖。

## 6. 幂等与补偿边界

- 原始事件：`shopId + eventId` 唯一；重复 webhook 仍返回 202，`duplicate=true`，不等于处理成功。
- 外部订单：`shopId + externalOrderNo` 与内部订单一对一；不会将同一外部订单映射到两个 CRM 客户。
- 商品：`shopId + externalSkuId` 唯一且必须 ACTIVE；未映射或数量无效进入 `MAPPING_FAILED`。
- 客户：`shopId + externalCustomerId` 唯一，人工 `MANUAL/HIGH` 链接；昵称/手机号不是客户唯一 ID。
- 支付：渠道交易号唯一；Mock 提供方幂等键为 `shopId + ':' + externalTradeNo`，重复确认不重复发权益。
- 补偿从 cursor 继续，保存 nextCursor/最近成功时间；最多 10 页。外部故障仍需重试和对账，不能依赖 Kafka 自动补齐。

## 7. 脱敏与数据最小化

`mobile`、`phone`、`nickname`、`name`、`displayName`、`contactName`、`address`、`idCard`、`buyerName` 在递归 raw 脱敏中替换为 `***`。异常文本最多 1000 字符，且不得包含签名、密文或对象内容。测试仅使用虚构 ID，不使用真实客户资料。

## 8. 实际 Outbox（仅发布侧）

| event_type | 实际 aggregate | payload | topic |
|---|---|---|---|
| `youzan.order.processed.v1` | `youzan`（relay 兼容 `youzan_order`） | `shopId/externalOrderNo/orderId` | `crm.youzan.events.v1` |
| `youzan.sync.issue.v1` | `youzan`（relay 兼容 `youzan_sync_issue`） | `eventId/issueType/status=OPEN` | `crm.youzan.events.v1` |
| `youzan.sync.completed.v1` | `youzan` | `shopId/received/processed/issues` | `crm.youzan.events.v1` |

`TradingMapper.xml` 的 `insertOutboxEvent` 采用 `ON DUPLICATE KEY` 非覆盖写入：并发重复 `sync.completed` 不覆盖既有 Outbox，也不把重复写入当成新的供应商事件。

`order.paid.v1` 仍走 `crm.order.events.v1`，其 `verificationMethod` 可为 `MANUAL_REVIEW` 或 `PROVIDER_CALLBACK`。这些发布不证明存在业务 consumer 或 Inbox 消费去重。

## 9. 错误与验收边界

- 400：请求字段、JSON 或幂等键格式错误。
- 401：未认证，或 Mock 签名缺失、无效、过期、真实接入禁用。
- 403：缺少管理权限或数据范围不足。
- 404：订单、客户、异常或映射目标不可见。
- 409：版本/状态冲突、重复键、异常已解决或终止。
- 422：真实接入未获 Q11 授权，或 SKU 权益规则不完整。

映射失败、客户未确认和支付不一致主要进入异常队列，不能误写成 webhook 重复事件应返回 409。联调测试仅覆盖 Mock HMAC 正误/过期、支付与待支付 fixture 的时间语义等，不宣称真实有赞已接入。

官方文档入口仅作后续授权后核对：https://doc.youzanyun.com/ 。实际店铺类型、接口目录和字段必须以 Q11 确认材料为准。
