# 42 有赞订单、支付与同步适配（P1-1 Mock + P1-1R 真实接入预建）

## 1. 边界与禁用状态

当前交付包含 **MockYouzanAdapter、内部适配 API、映射、补偿与异常队列**，以及 **P1-1R 真实店铺配置、Token/订单客户端、官方消息和同步任务预建**。真实店铺仍未授权联调，不能宣称生产有赞已接通。

- Q11（店铺类型、授权、订单/退款订阅、限流与字段规则）未确认，`FEATURE_REAL_YOUZAN` 默认仍为 `false`。具备 `integration:runtime:manage` 的管理员可在有赞页面保存当前租户的全局开关，覆盖环境默认值并即时生效；保存动作写审计，但不代表 Q11 已验收。
- 本地 `local` profile 使用 Mock fixture；真实调用还需已保存店铺配置并启用 `syncEnabled`。不满足条件时使用 `DisabledYouzanAdapter`，真实拉取返回 `PENDING_BUSINESS_RULE`/422。
- `RealYouzanAdapter` 使用官方 `/auth/token`（常规取 Token 传 `refresh=false`，显式强制刷新传 `refresh=true`）、`youzan.trades.sold.get/4.0.2` 和集中配置的订单详情版本（默认 `4.0.2`）。列表返回完整 `full_order_info`（含 `remark_info.trade_memo`）时直接映射为内部事件，避免逐单 N+1 调用 `youzan.trade.get` 消耗配额；仅当关键详情字段或 `remark_info.trade_memo` 缺失时自动回退调用 `youzan.trade.get/4.0.2`。`YouzanRemoteClient` 解析有赞网关错误体 `gw_err_resp`（如 `4202`/`4203`/`40010`/`4101`），连接测试在 Token 过期时自动强制刷新重试一次。`YOUZAN_API_BASE_URL` 只允许服务端受控配置，用于模拟联调，不开放前端任意地址。
- 店铺 `clientSecret/accessToken/refreshToken` 使用 AES-GCM 密文保存；入参自动去除首尾空白，新建禁止空白密钥；API 只返回 `secretConfigured` 和连接状态，不回显密钥或 Token。仅修改 `shopName` 或 `syncEnabled` 时保留已验证的 `CONNECTED` 状态与缓存 Token；仅当修改 `clientId` 或 `clientSecret` 时清空旧 Token 并重置为 `UNVERIFIED`。
- 官方消息入口为 `POST /api/v1/webhooks/youzan/official`，使用 `Client-Id/Event-Type/Event-Sign`，与 `/api/v1/webhooks/youzan` 的开发 Mock HMAC 完全分离。验签通过后按有赞云官方协议返回 **HTTP `200 OK`** 与 `{"code":0,"msg":"success"}`；其中 `test=true` 控制台验证消息（允许在店铺尚未开启 `syncEnabled` 或测试报文缺失/占位 `kdt_id` 时按已配置 `clientId` 完成严格开关与 MD5 验签）、暂不自动同步的退款消息及非订单事件仅返回 200 ACK，不创建订单/支付任务或写入异常。
- 官方订单类消息验签返回 200 ACK 前先落库，30 秒后查询订单详情，再进入既有映射和支付链路；失败按 60 秒重试。消息本身不作为资金到账凭证。
- 已关闭状态（`TRADE_CLOSED` / `TRADE_CLOSED_BY_USER`）映射为 `ORDER_CLOSED`：未建 CRM 订单的关闭单直接标记 `PROCESSED` 留痕审计，不建脏草稿单也不写入异常（且当 `paidAt` 为空时自动收敛同店铺同外部单号下历史 `ORDER_PENDING`/`WAIT_PAY` 事件滞留的 `OPEN` 异常并记入审计，保留历史 `ORDER_PAID`/`PAYMENT_MISMATCH` 异常供人工核查）；已建未支付（`DRAFT` / `PENDING_PAYMENT`）订单自动取消为 `CANCELED`；已支付历史订单不直接覆盖或自动退款，记入 `PAYMENT_MISMATCH` 人工异常队列提醒核实退款。
- 本阶段不交付退款同步，不宣称业务 Kafka consumer、Inbox 消费去重或真实店铺联调已完成。

字段级 fixture 映射和真实对接交接清单见 [42_有赞字段映射与交接.md](42_有赞字段映射与交接.md)。

## 2. 当前调用链

```text
内部管理 API / Mock webhook
  → YouzanManagementService / YouzanEventService
  → YouzanAdapterRouter
      ├─ local：MockYouzanAdapter（固定脱敏 fixture）
      └─ 其他或真实拉取：DisabledYouzanAdapter（禁用）
  → 原始事件 + SKU/客户/订单映射 + 异常队列
  → 订单与支付领域服务（不是把 Adapter DTO 当订单实体）
  → Outbox relay（仅发布侧）
```

原始 JSON 经过递归脱敏后保存 `payload_masked_json`，完整原文使用 AES 保存 `payload_cipher`。API 仅向具备 `integration:youzan:manage` 的管理员返回 `payloadMaskedJson` 脱敏文本，普通 `order:read` 用户该字段为 null；绝不返回 `payload_cipher` 或原始明文。Raw 处理状态与内部订单字段分开呈现，前端原始详情仅供管理员排障并默认折叠。

### 3.1 真实同步策略与游标

- 首次同步按 `start_created/end_created`，超过 90 天的历史区间自动裁剪为最多 90 天的窗口分段；订单列表使用 `page_no/page_size`，单页最多 100，页码最多 100。
- 自动增量按 `start_update/end_update`，策略可配置 60–86400 秒间隔和 0–3600 秒重叠。调度执行时同样裁剪超过 90 天的窗口并跨多页循环拉取，仅在窗口完整完成后才推进 `lastSyncAt`；`next_run_at` 支持 Web 直接修改下次执行时间，保存后无需重启；每次认领后按间隔推进，过去时间视为立即执行。窗口与页码 JSON 最长 2048 字符，和 Mock 数字游标兼容存储。
- `youzan.trades.sold.get/4.0.2` 返回完整 `full_order_info` 时直接映射为内部标准事件，避免逐单调用 `youzan.trade.get` 浪费配额；仅当任一关键详情字段缺失时自动回退调用 `youzan.trade.get`。元字符串金额使用 `BigDecimal` 精确转整数分；客户键为 `yz_open_id`，SKU 键为 `item_id:sku_id`。
- 每次手动/自动执行记录 `crm_youzan_sync_job`，只有接收、处理、重复和异常统计；`PARTIAL` 不等于全部成功。数据库策略版本、店铺租约和任务租约共同用于避免同店铺并发调度。
- `payload_cipher` 保存内部标准事件，`provider_payload_cipher` 保存官方原始报文；公开 `payloadMaskedJson` 由原始脱敏字段与内部标准字段合并，不包含密文。

### 3.2 安全与可靠性加固（V14 与官方协议修正）

- `youzan.sync.completed.v1` 的 Outbox `event_id` 使用 `shopId + SHA-256(nextCursor)`，不再把可变长 JSON 游标直接拼入事件键；相同游标保持确定性幂等。
- 订单列表到第 100 页且仍有数据时强制将当前时间窗按整秒二分续跑；不能继续细分时进入异常，禁止静默漏单。
- 官方消息验签通过后返回 HTTP `200 {"code":0,"msg":"success"}`；`test=true` 与非订单事件直接返回 200 ACK 不落单。订单类消息重复到达但尚未 `PROCESSED` 时会重新安排详情查询；启动和每 30 秒扫描超时 `RECEIVED/RETRY`，覆盖重启丢失的内存定时任务。
- `YouzanRemoteClient` 统一解析 `gw_err_resp` 网关错误（含 `4202`/`4203`/`40010`/`4101`）；常规取 Token 传 `refresh=false`，仅在明确 Token 失效时按店铺单飞传 `refresh=true` 强制刷新并仅重试一次（含 `testConnection` 自动刷新一次）；店铺级调用间隔默认 100ms，429 最多三次调用并支持 `Retry-After`，不无限退避。
- `crm_youzan_shop_config` 店铺租约与 `crm_youzan_sync_job` 任务租约在任务开始获取、跨页续跑时同步续期、成功/失败均释放。过期 RUNNING 任务标 FAILED 并释放过期租约，后续从持久化游标续跑。
- 官方匿名回调限制 1MB（Content-Length 超限与 chunked 流式超限均返回 413）和最多 64 层嵌套（按 400 拒绝）。
- 脱敏覆盖导购/销售员手机号、姓名、员工 ID、外部平台身份、收货电话和留言备注；系统操作员按当前租户选择 ACTIVE ADMIN，不再固定用户 1。
- `sync/reconcile` 改为 `integration:youzan:manage`，普通 BUSINESS 角色不能通过同步间接触发支付确认。

## 4. Mock webhook 安全约定

以下仅是 **开发 Mock 协议**，不是有赞官方签名规范：

- 请求头：`X-Youzan-Mock-Signature`、`X-Youzan-Mock-Timestamp`（Unix 秒）。
- 签名：`hex(HmacSHA256(timestamp + rawBody))`，密钥来自 Mock 环境配置。
- 时间窗：当前时间与 timestamp 的绝对偏差不得超过 300 秒；缺签名/时间、伪造或过期均返回 401。
- 必须对原始请求体验签，不能用重新序列化后的 JSON 代替原文。验签通过后才解析事件、落 raw 并异步处理。
- 密钥不得写入文档、日志、fixture、异常消息或仓库。不得在交接材料中打印环境实际密钥。
- webhook 允许匿名调用但依赖 Mock 签名，不是安全豁免；真实回调安全规则仍待 Q11 确认。

## 5. 处理状态与可信支付

### 5.1 原始事件

- 验签通过首次入库：`RECEIVED`；同 `shopId + eventId` 已存在则按重复事件返回。
- 映射和处理成功：`PROCESSED`，同时保存内部 `orderId`。
- 可分类失败：`MAPPING_FAILED`、`CUSTOMER_UNRESOLVED`、`PAYMENT_MISMATCH`，并创建/更新 OPEN 异常。
- 其他可重试失败：`RETRY`，记录 `nextRetryAt`；schema 的 `DEAD_LETTER` 不代表当前已有自动死信 consumer。

### 5.2 异常队列

`OPEN → RETRYING → RESOLVED`。只有 OPEN/RETRYING 可人工重试；RESOLVED/DEAD 不可重试，返回 409。重试后仍失败会保留异常和脱敏原因，不伪造成功。

### 5.3 订单与支付

- 外部订单先经 SKU 映射、客户人工链接和订单快照规则校验；未匹配不得创建可用权益。
- `ORDER_PAID` 必须有交易号、支付时间、正整数分金额，且金额等于内部应付金额，否则 `PAYMENT_MISMATCH`。
- 新订单先 DRAFT；满足支付条件后提交 PENDING_PAYMENT，再由支付域确认 PAID 并发放权益。
- 支付回调使用 `paymentChannel=YOUZAN`、`verificationMethod=PROVIDER_CALLBACK`；人工支付仍保留 `MANUAL_REVIEW`。
- `externalUpdatedAt` 不晚于已处理版本时按重复/旧版本处理，不用旧状态覆盖新事实。已支付历史不可由普通同步覆盖。

## 6. 幂等与补偿边界

- 原始事件：`shopId + eventId` 唯一；Mock webhook 重复事件返回 202 + `duplicate=true`，官方 `/webhooks/youzan/official` 按有赞云协议返回 200 `{"code":0,"msg":"success"}`，两者均不等于业务处理成功，也不重复建单或发权益。
- 外部订单：`shopId + externalOrderNo` 与内部订单一对一；不会将同一外部订单映射到两个 CRM 客户。
- 商品：`shopId + externalSkuId` 唯一且必须 ACTIVE；未映射或数量无效进入 `MAPPING_FAILED`。
- 客户：`shopId + externalCustomerId` 唯一，人工 `MANUAL/HIGH` 链接；昵称/手机号不是客户唯一 ID。
- 支付：渠道交易号唯一；Mock 提供方幂等键为 `shopId + ':' + externalTradeNo`，重复确认不重复发权益。
- 补偿从 cursor 继续，保存 nextCursor/最近成功时间；最多 10 页。外部故障仍需重试和对账，不能依赖 Kafka 自动补齐。

## 7. 脱敏与数据最小化

`mobile`、`phone`、`nickname`、`name`、`displayName`、`contactName`、`address`、`idCard`、`buyerName` 在递归 raw 脱敏中替换为 `***`。异常文本最多 1000 字符，且不得包含签名、密文或对象内容。测试仅使用虚构 ID，不使用真实客户资料。

## 9. 错误与验收边界

- 400：请求字段、JSON 或幂等键格式错误。
- 401：未认证，或 Mock 签名缺失、无效、过期、真实接入禁用。
- 403：缺少管理权限或数据范围不足。
- 404：订单、客户、异常或映射目标不可见。
- 409：版本/状态冲突、重复键、异常已解决或终止。
- 422：真实接入未获 Q11 授权，或 SKU 权益规则不完整。

映射失败、客户未确认和支付不一致主要进入异常队列，不能误写成 webhook 重复事件应返回 409。联调测试仅覆盖 Mock HMAC 正误/过期、支付与待支付 fixture 的时间语义等，不宣称真实有赞已接入。

官方文档入口仅作后续授权后核对：https://doc.youzanyun.com/ 。实际店铺类型、接口目录和字段必须以 Q11 确认材料为准。

## 10. 有赞客户拉取与 CRM 正式建档（V64）

本能力在既有有赞订单同步之外，提供将有赞店铺客户按受控批次拉取并创建为 **CRM 正式客户主档**（`crm_customer` + `crm_customer_identity` + `crm_youzan_customer_link`）的专用通道。建档动作严格与订单账本及权益发放解耦，绝不会因拉取客户自动确认订单或发放权益。

### 10.1 双数据源模式与适配器路由

| 数据源模式（`sourceMode`） | 调用有赞官方接口 | 适用场景与前置权限 | 底层固定页大小 / 翻页上限 |
|---|---|---|---|
| `SCRM_LIST` | `youzan.scrm.customer.list`（默认 `1.0.0`，`page_no`/`page_size` 分页，按创建时间降序，可通过 `YOUZAN_SCRM_CUSTOMER_LIST_VERSION` 配置） | 拉取有赞店铺**全量客户**（含未下单潜客），需在有赞云开通「店铺客户信息同步」能力包（`youzan.scrm.customer.list/1.0.0`）；未开通时返回 `422 PENDING_BUSINESS_RULE` 并引导切换 `ORDER_BUYERS`；单窗命中 `total >= 10000` 或业务码 `142710032` 自动二分切窗 | `20` 条/页，单窗最多 `500` 页（上限 `10000` 条） |
| `ORDER_BUYERS` | 复用既有 4 个已实测接口：`youzan.trades.sold.get`（`4.0.2`）、`youzan.trade.get`（`4.0.2`）、`youzan.users.info.query`（`1.0.0`，`result_type_list=[0,1,2,9]`）、`youzan.scrm.customer.get`（`3.0.0`，按明文 `mobile` 或 `fans_type + fans_id` 查询） | 无需新申请接口权限，直接按成交订单提取买家并去重；默认回溯过去 365 天，或按请求 `startDate`/`endDate`（`Asia/Shanghai`）自动按 ≤89 天切窗 | `50` 条/页，单窗最多 `100` 页 |

- **密文过滤与资料补全**：`OfficialYouzanCustomerPullClient` 自动过滤有赞安全密文（`$...$1$`）避免污染姓名、昵称、手机号、备注、城市或标签；当 `enrichProfile=true`（默认）且处于 `ORDER_BUYERS` 模式或姓名/手机号/生日/备注/城市/标签任一缺失时，调用 `youzan.users.info.query`（`1.0.0`）、`youzan.scrm.customer.get`（`3.0.0`）以及在标签为空时补调 `youzan.scrm.tag.relation.get`（默认 `4.0.0`，可通过 `YOUZAN_SCRM_TAG_RELATION_VERSION` 配置）补全真实姓名、昵称、手机号、生日、商家备注、省市（绝不采集详细街道门牌地址）与有赞原标签；若辅助补全接口未开通，仅写入非致命 `warnings` 而不中断整批建档。
- **城市/标签字典治理与已建档老客非破坏性回填**：
  - 城市严格按当前租户启用中的 `cities` 字典匹配（支持去“市/自治州”后缀及省市文本），未命中留空绝不写脏编码；
  - 有赞标签严格遵循 `customerTags` 字典治理：复用已有 `ACTIVE` 标签，尊重已停用 `INACTIVE`/`ARCHIVED` 标签不自动启用，仅当操作人具备 `customer:tag:manage` 时为新标签自动建 `ACTIVE` 字典项（代码 `YZ_TAG_<12位哈希>`）；
  - 重置游标重拉已绑定有赞客户且 `enrichProfile=true` 时，自动执行非破坏性回填：仅当 CRM 原 `city_code`/`remark`/`birthday` 为空时补全，标签仅 `insertIfAbsent` 增量追加，绝不覆盖运营已维护字段，也不触碰 `MOBILE_CONFLICT` 冲突老客。
- **环境隔离与路由**：`YouzanCustomerPullClientRouter` 在租户开启 `youzanRealEnabled` 时，强制校验店铺已保存配置且 `syncEnabled=true`（否则返回 `409`），绝不静默降级至模拟数据；未开启真实开关时，仅 `local` profile 可路由至 `@Profile("local")` 的 `MockYouzanCustomerPullClient`（仅针对 `MOCK-SHOP-001` 返回纯合成样本），非 `local` 环境显式返回 `422 PENDING_BUSINESS_RULE`。

### 10.2 持久化断点游标与增量续拉机制

1. **恒定页长 + 页内偏移防错位**：无论前端本次请求拉取 `10`、`20`、`50`、`100`、自定义 `1–500` 还是「全部拉取」，后端调用有赞底层接口始终保持固定页大小（`SCRM_LIST` 固定 `20`，`ORDER_BUYERS` 固定 `50`），并将精确断点 `(anchorStart, anchorEnd, windowStart, windowEnd, pageNo, itemOffset)` 持久化到 `crm_youzan_customer_sync_cursor.cursor_json`。因此连续执行 `10 → 10 → 20 → 全部` 时每次严格从上一批结束后的下一条续拉，**绝不错位、不漏条、不重复拉取**。
2. **分批模式（`BATCH`）与全部模式（`ALL`）**：
   - `BATCH`：单次目标处理 `limit`（`1–500`，缺省 `20`）条去重后非已绑定客户，内置最大翻页保护避免死循环或网关超时。
   - `ALL`：单次 HTTP 调用最多拉取 `limit`（缺省 `200`，上限 `500`）且最多扫描 `30` 页；若仍有未拉完记录则返回 `hasMore=true`，由前端自动发起下一批（每批携带独立 `Idempotency-Key`，支持随时点击「停止拉取」中断）直至 `hasMore=false`。
3. **超大时间窗自动二分切窗**：当任一时间窗总量超过单窗最大可翻页容量触发 `YouzanCustomerWindowTooLargeException` 时，服务自动按 `(windowStart, windowEnd)` 中点二分切窗（若 `windowStart` 为空则以 `2015-01-01T00:00:00Z` 兜底），避免静默截断漏客。
4. **全量完成后自动转增量与手动重置**：当前周期扫完（`hasMore=false`）时自动将本轮截止锚点 `anchorEnd` 写入 `last_anchor_at`；下次再拉取时自动从 `last_anchor_at - 60s` 起增量拉取新增客户。若需从头重扫，可在请求传入 `resetCursor=true` 或调用 `POST /api/v1/integrations/youzan/customer-sync/cursor/reset` 清空断点游标（已建档绑定客户仍会自动跳过）。

### 10.3 归属管家校验、防重与手机号盲索引冲突规则

- **归属管家与字典预检**：批次启动前通过 `CustomerExternalImportService#validateImportTarget` 强制校验：
  - 操作人必须为内部员工（`EMPLOYEE`），严禁合作机构账号（`INSTITUTION`）访问任何客户同步接口；
  - 目标 `ownerStaffId` 必须是在职的 `MANAGER` 或 `MANAGER_LEAD`（`StewardDirectory#isEligibleSteward`），且位于当前操作人可分配的数据范围内（`StewardDirectory#canAssignTo`），跨范围返回 `403`；
  - 可选 `sourceCode` / `channelCode` 若填写则必须为启用中的 `customerSources` / `customerChannels` 字典项。
- **客户主档唯一性与三层防重**：
  1. 客户唯一 ID 仍为服务端生成的 `crm_customer.id` / `customer_no`（`C0000000001`），绝不以手机号、微信昵称或 `yz_open_id` 作为主键。
  2. 先查 `crm_youzan_customer_link(tenant_id, shop_id, yz_open_id)`：已存在则调用 `ensureIdentityLinked` 补齐 `crm_customer_identity` 并记 `SKIPPED_EXISTING`；再查 `crm_customer_identity(tenant_id, identityType, sourceApp, externalId)`：已存在则补齐 `crm_youzan_customer_link` 并记 `SKIPPED_EXISTING`。
  3. **手机号盲索引冲突绝不覆盖老客户**：对未绑定外部身份的客户，将明文手机号归一化并计算 HMAC 盲索引（`mobile_hash`）查询 CRM 活跃客户；若命中已有 CRM 客户，**绝不新建重复档案，也绝不覆盖原客户姓名/手机号/归属管家**，而是记为 `MOBILE_CONFLICT`，将命中的 `conflictCustomerIds` 与 `conflictCustomerNos` 写入批次明细，供运营一键跳转至「人工客户链接」页签人工核对关联。
  4. 无冲突时以单条独立事务（`REQUIRES_NEW`）写入 `crm_customer`（手机号仅落 AES-GCM 密文与 HMAC 盲索引）、`crm_customer_identity` 与 `crm_youzan_customer_link`（`linkType=STRONG, confidence=HIGH`），并尝试关联历史未解风控单；单条异常仅记 `FAILED` 与脱敏原因，不中断整批其余客户。

### 10.4 权限、幂等、并发锁与审计

- **权限**：只读接口（`/status`、`/runs`、`/runs/{runId}/items`）要求 `integration:youzan:manage`；写接口（`/pull`、`/cursor/reset`）同时要求 `integration:youzan:manage` 与 `customer:write` 及 CSRF 校验；全接口拒绝机构账号并按 `tenant_id` 强隔离。
- **幂等与并发互斥**：`POST /pull` 强制要求 `Idempotency-Key`（1–128 字符），同键同参幂等重放既有批次结果；`crm_youzan_customer_sync_run` 通过生成列 `running_shop_key` 与唯一键 `uk_yz_cust_run_running(tenant_id, running_shop_key)` 保证同租户同店铺同模式同时仅运行 1 个批次（并发冲突返回 `409`），支持 `lease_until` 超时自动回收并在 `finally` 块中将异常任务标记 `FAILED` 可靠释放锁。
- **审计与脱敏**：批次结束记录 `YOUZAN_CUSTOMER_SYNC`，重置游标记录 `YOUZAN_CUSTOMER_CURSOR_RESET`，单客新建由客户域记录 `CUSTOMER_CREATE`；所有日志、审计快照、表字段与 API 响应均严禁出现明文手机号或明文微信 OpenID。
