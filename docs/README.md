# 鲸选美学 CRM — V2.0 原型正式开发资料包

> 开发文档版本：1.0.0（2026-10-23）｜原型基线：V2.0｜状态：**可用于分阶段研发，未确认的业务规则不得自动视为既定制度**。

## 这份资料包解决什么问题

将已有的纯前端 `V2.0_交互原型.html` 逐步建设为具备真实账号、权限、MySQL 事务、Redis、Kafka、企业微信官方接口、有赞订单接口、文件管理、AI 辅助服务和医院核销闭环的可部署系统。

**原则：原型管页面与交互，文档管业务和安全；代码与上线以真实接口与测试验收为准。** 原型的模拟数据、前端权限、弹框确认、假 AI/假有赞和浏览器本地存储不得直接用于生产。

## 建议的技术基线

- Java 21 / Spring Boot 3.5.x / Maven / Spring Security / MyBatis（或 MyBatis-Plus，只选一个）/ Flyway / Bean Validation
- Vue 3 / TypeScript / Vite / Element Plus / Pinia / Vue Router
- MySQL 8.4 LTS（InnoDB，utf8mb4）；Redis；Apache Kafka（KRaft）；MinIO/S3；Python FastAPI AI Worker
- 本地 Docker Compose，后续根据运维能力部署为分离式或容器编排；开发、测试、生产不同配置
- 版本不是永久钉死：依赖锁文件在项目初始化时确认可用的安全补丁版本，升级需 ADR 和回归测试

## 给大模型的第一个指令

> 先阅读 `06_大模型开发指令/60_AGENTS.md`、`00_项目管理/02_待确认事项与决策登记.md` 和 `01_需求与产品/11_业务流程与状态机.md`。按照 `61_分阶段Prompt.md` 的 P0 阶段先建项目骨架与数据库迁移。不要一次性生成全部业务模块；每阶段必须输出测试结果、迁移脚本、API 文档和变更记录。

## 约束说明

1. **禁止臆造**：真实企业微信、有赞、医院的接口参数和能力需按开通后的官方文档、账号权限联调确认。
2. **高风险数据**：订单支付、成功退款、正式核销、已生效合同审批等不得直接 UPDATE 覆盖历史事实。
3. **权限生效点在后端**：隐藏菜单不是授权；机构账号按 `institution_id` 限制，管家按 `owner_staff_id`/团队范围限制。
4. **不要混淆「选 N 项」与「使用 N 次」**，每一项是有独立规则的套餐配置。
5. **数据库与事件**：MySQL 是最终一致的业务事实来源；Redis 是可失效缓存；Kafka 是异步传输，不负责余额最终值。
6. 开发用示例数据为虚构；接真实数据前要落实合法授权、权限、脱敏、日志与保存期限。

## 本包的可执行附件边界

`07_可执行参考/schema.mysql8.4.reference.sql` 是用于理解数据模型及开发起步的**基线参考脚本**，不等于已经生产审计的完整上线迁移；`07_可执行参考/docker-compose.dev.yml` 是**开发单机环境**，不是高可用生产集群；OpenAPI 和 Event 示例定义公共约定，所有业务路径需在分阶段研发中按规范完善。
