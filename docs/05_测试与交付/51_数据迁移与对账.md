# 51 旧智能表格、订单、客户、医院的数据迁移

## 1. 迁移源
依据目前已提供的智能表格截图、管家操作规范和原型，至少包括：客户信息表（23字段）、机构信息维护表、产品组合明细表、产品子项目明细表、合作渠道、客户日跟进、管家售卖、订单核销、管家业绩、商务业绩及经营分析。**截图字段显示不完整或公式未取得时，不可假设含义。**

## 2. 数据采集阶段
导出每张原表**全字段**CSV/XLSX，包含隐藏字段、公式、关联表主键、选项字典、创建/修改人、时间、附件引用、表间引用ID；保存只读原始导出副本（带 SHA256、版本、导出时间）。需要原系统API才取的字段必须显式登记缺口。

## 3. 迁移原则
- CRM `customer_id` 自动生成，原手机号不作为主键；手机号缺失允许空，昵称不得填电话字段。
- 保留 `legacy_table`, `legacy_row_id`, `legacy_values_json`, `migration_batch_id`, `source_updated_at` 等来源血缘信息（建议补迁移映射表 `legacy_source_map`）。
- 不自动把历史公式值变成新的会计计算值；旧值与新口径同时保存，差异进入人工核对清单。
- 历史售卖订单、核销次数必须能对应订单行和项目；无法匹配的记录导入“待核验”，**不生成可用权益**。
- 成交日期≠支付成功；历史有交易凭证或来源证明才确认支付；否则进入待核实。
- 同手机号、不同管家、多个微信身份生成合并候选，由人工确认。

## 4. 迁移步骤
1. 创建全量映射模板：旧表字段 → 新实体字段 → 类型/选项 → 业务规则 → 样例与问题编号。
2. 清洗标准化日期/金额、城市/项目字典、客户主档与身份别名、机构名称与机构ID、产品SKU。
3. 在 staging 一次全量导入非资金主数据，核对记录数/字段非空率/重复候选。
4. 订单与付款/退款按原始可靠凭证导入；对账通过才发放历史权益批次。
5. 项目核销逐笔导入、保留实际医院、日期、次数、原始单号和录入人；重复/缺来源单据进入待核验队列。
6. 业务抽样签字：客户余额、订单成功金额、退款、机构核销次数、业绩。
7. 预上线增量迁移，冻结旧表写入或采取双写计划；切换只读；上线后比对至少完整业务周期。

## 5. 迁移校验清单
`原表行数/有效行数/迁移成功/失败`、原始手机号空值比例、重复客户候选数、SKU未映射数、订单缺支付证据数、权益余额差异客户数、退款与核销不匹配次数、医院/日期为空记录。生成 CSV 差异清单，任何资金或次数不符都必须人工签字才能上线。

## 6. 回滚方案
迁移脚本要可重跑且幂等，按 `migration_batch_id` 管理。上线后若需回滚，则停止新业务写入、保护新产生的正式核销/订单事实，导出差异，再批准回滚/补偿；不允许直接恢复旧数据库覆盖已经发生的新核销。
