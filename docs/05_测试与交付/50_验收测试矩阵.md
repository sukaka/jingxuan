# 50 开发测试、端到端验收及并发矩阵

## 1. 测试分层
- 单元：领域状态机、金额分摊、权益计算、授权策略、字典状态、模型输出解析。
- MySQL 集成：使用 Testcontainers MySQL 8.4 实库，验证事务、外键、唯一约束、行锁、Flyway。
- Kafka 集成：Testcontainers Kafka，Outbox→Kafka→Inbox，验证重复、乱序、故障与 DLQ。
- 前后端契约：OpenAPI 型别生成校验；返回所有空值/权限错误。
- E2E：Playwright，按管理员/管家/机构账号演示业务闭环；不以断言页面可打开代替数据正确。
- 安全：越权、泄露、Webhooks 签名、导出、批量并发、文件 XSS/上传恶意内容。

## 3. 静态检查与工程门禁
- `mvn -q verify`、JUnit5、Spotless、Checkstyle/SpotBugs、依赖/secret扫描；前端 `npm ci && npm run typecheck && npm run lint && npm run test && npm run build`。
- 所有状态机测试用枚举/测试用例生成，不允许只测 Happy Path；测试必须验证 DB 最终状态、流水、Outbox、审计。
- Playwright 使用稳定 `data-testid`，为表单模拟慢网络、双击、刷新、权限变更与文件上传失败。

## 4. 业务验收脚本
1) 管家建客户→改标签→生成订单草稿→支付确认→查看多项目权益。
2) 给机构预约→院方确认接诊→到院→做服务→机构核销2次→客户余额准确→核销记录按医院可查。
3) 客户部分退款→财务审批/成功回执→权益回收按规则→医院账单查询影响。
4) 机构申请修改佣金→市场审→财务审→正式值更新→审计before/after；由机构打开页面查看新规则。
5) 商品SKU修改后重复有赞订单导入、企业微信消息重复归档、AI待办拒绝/确认、主管导出审计。

## 5. 不能通过的发布闸门
任何负余额、重复扣减、交易金额浮点、签名绕过、机构越权、未经审核敏感字段直接生效、聊天数据超授权可见、已成功退款与实际回执不匹配，均为 P0 上线阻断。
